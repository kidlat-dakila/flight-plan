Say what happens at this place, as a reader of the product would: "A shopper clicks Remove", "The orders of the account are loaded". Read the code of the node first, so the label names the element the user acts on or the data that is fetched.

- **An event.** Start with who acts, then the action and what it is on: `A shopper clicks "All"`. Leave the name of the component and of the handler out: the row shows the name of the code under your label.
- **A data fetch.** Say what is loaded, not how: `The stock of the product is loaded`, not `useQuery runs`.

Keep the same shape and tense on every trigger label of one diagram.
