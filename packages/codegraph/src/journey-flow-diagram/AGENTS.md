# packages/codegraph/src/journey-flow-diagram

The Journey Flow Diagram of a segment, drawn from the chains of its group. Read [Journey Flow Diagram](../../../../docs/vocabulary/journey-flow-diagram.md) before changing anything here. The rules of [packages/codegraph/AGENTS.md](../../AGENTS.md) hold here too.

## Rules

- **A journey is drawn from the group in memory.** `generateJourneyFlowDiagram({ group, importGraphGroup, scope })` in `index.ts` takes the `ASTCodeGroupGraph` that `linkCodeGroupGraph` made and returns one `JourneyFlowDiagram` for a segment, or `null` when no chain leads to a change in it. The diagram holds the group, the import graph and every block as the same objects it was handed.
- **A node is a root block, or a block inside one that something triggers.** `walkChains` starts at every top of `diffChains` and follows `nextBlocks`. `isNodeBlock` in `node-blocks.ts` says which blocks are nodes, as the table of [Nodes](../../../../docs/vocabulary/journey-flow-diagram.md#nodes) does: a root block that is no `root-statement` and no folded value, an event, an effect, a callback, a route, a resolver and a middleware inside a `component` or a `root-statement` (`hasNodesInside`), and, in any root block, a block whose `catalogue` says `isOwnNode`, and a named function directly in the body of a callback whose `catalogue` says `holdsOwnNodes` (`isKeyedFunction`). Nothing inside such a block is a node (`isInsideOwnNode`). Every other root block is one node with all that is written in it. The call of a `state` or a `derived`, a callback that runs in place, a function written in place of an event or a callback and a function an event of the same root block is handed by name (`eventHandedTo`, read from `usedBy`) are no nodes. Such a handed function belongs to the node of its event: `nodeBlockOf` and `nodeBlockAround` climb from it to that event, not to its parent. `isStepBlock` says which other blocks are steps, for the band: a function or a method, and a block that is executed anywhere but on the way to the `return` of a component or a hook. `nodeBlockOf` gives the node block a block is in, or `null` for a block of a `root-statement` that no node holds, and `nodeBlockAround` the one around a node block. A block with no node block is in no node, and a step that leaves it or reaches it is no edge.
- **A value that is not exported is folded into the nodes that read it.** `isFoldedValue` in `node-blocks.ts` says which: a `root-variable` that is not exported, that holds no block of the types that run (`RUNNING_TYPES`) and that a block in a node reads (`usedBy`). It is no node, and `foldedValueOf` gives the folded value a block is in. `listFoldedValueHolds` in `index.ts` gives each node with a step into a folded value, directly or through another folded value, the shown blocks of that value, so `toJourneyNode` holds them and `listListedBlocks` lists the value as a step. `stepsInto` carries a step into a folded value on to what it leads to. The Code Walkthrough reads a folded value as it reads a node, so its waypoints do not change. [Values that are not exported](../../../../docs/vocabulary/journey-flow-diagram.md#values-that-are-not-exported) has the rule.
- **Every block on a chain and every changed block is in the nearest node around it.** `listShownBlocks` gathers them, but for a root block of a file outside the segment that holds a block leading only to the change of another line (`handsOverOtherLines`, read from `leadsOnlyToOtherLines`), such as a route table that names the pages of other segments, it keeps only the blocks the walk passes through, `listNodeBlocks` gives the node block of each and every node block around it up to the root, root blocks first, and `listNodes` makes one node per node block.
- **An edge is a step between two nodes, or a node inside another.** `listNodeSteps` in `node-blocks.ts` turns the steps of the walk into steps between nodes: a step that stays in a node or only goes further inside it is none, a step through a block of a node around is carried on to what it leads to, and so is a step from inside a step block through a value of its own node, so that the band can join the row of the step. `listHeldNodeEdges` adds one edge from the node around each inner node. `listEdges` keeps each pair once. The band reads `listNodeSteps` too, so the lines of the page and the edges of the diagram cannot disagree.
- **`cards.ts` builds what an author adds.** `readFileGraph` reads one file as a group of its own, `listCardBlocks` lists the root blocks a card can stand for, `buildBlockCard` and `buildLinesCard` make the node, and `listCardRows` gives the rows of any node: the stored `rows`, or the rows the page lists from its `codeBlocks`. Editing a diagram is the backend's `procedures/edit-journey/`.
- **A node holds its blocks in the order they are written.** `toJourneyNode` puts the block of the node first, then the blocks a chain passes through and the blocks with a change inside it, down to the blocks that are nodes of their own. `diffCodeBlocks` are those with a change, and `triggerLabels` those after the first of the types `render-event`, `code-event` and `data-fetch`, each with a `null` label. `blockLabels` are the listed blocks of the node, which `listListedBlocks` in `listed-blocks.ts` names: its arguments, state, hooks, effects and steps, each with a `null` label for an agent to write.
- **A step is a statement, and the statements that follow each other are one step.** The folding is in `step-folding.ts`, which the Code Walkthrough reads too, each with `StepRules` of its own: `statementOf` gives a step the outermost declared value, property or nameless function around it, `isStepRow` folds what is inside a listed block into its row and keeps a changed step inside a condition, a loop, a `try-catch` or a named function, and `listRuns` joins the statements that follow each other and call nothing out (`isFoldedStatement`). `listed-blocks.ts` names the candidates of a node and gives the rules of a journey: a statement that is itself a call out (`isExternalCall`) is of the kind `call`, and a call out among the blocks of a node is a candidate though it has no change, so the line to what it calls has a row to leave. A block calls out by its type, by a next block in another node, or by a call symbol that names a function, a hook, a method, a component or a class outside the node or an import of a library (`callsCodeOutside`). A listed block carries its `statements`, the block of the first one being the block it is listed by. [Steps](../../../../docs/vocabulary/journey-flow-diagram.md#steps) has the rules.
- **Components that render each other are nested.** `listComponentParents` finds the edges between two `component` nodes and gives each rendered component the first component that reaches it from a top. `countImportersByPath` counts, for each file, the files of the group that import it, directly or through other files, and the components are read in that order, the fewest first. A top is a component no other renders, and a loop is opened at its first component in that order, so a component is never inside one its file imports. `nestNodes` moves a child into `children` and leaves its edges in place.
- **An entry segment keeps its own paths.** With a `scope`, `reachWithin` keeps the steps that lead to a change in the files of the segment, and below a changed root block of the segment, the steps that lead to a change of the shared segment. The shared segment has a `scope` of its own files. `withoutOtherLines` then drops every block of a file in `otherLineFilePaths`, the changed files of the other entry segments, and every block that leads to a change only through one, so no diagram draws the line of another segment.
- **`stored.ts` holds the two other forms.** `storeJourneyFlowDiagram` replaces every block with its id and leaves the group out, `linkJourneyFlowDiagram` puts them back from a group, and `flattenJourneyNodes` gives every node at any depth as one entry with its `parentId` and no children. Snapshots read the stored form, and the MCP tools the flat one.
- **`listJourneyPaths` in `paths.ts` gives every path of a diagram as a line**, from a node nothing leads to down to its last node, for comparing two diagrams.
- **`listJourneyNodes` gives every node at any depth.** Everything that reads the nodes of a diagram as a list goes through it.
