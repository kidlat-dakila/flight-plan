# packages/codegraph/src/journey-flow-diagram

The Journey Flow Diagram of a segment, drawn from the chains of its group. Read [Journey Flow Diagram](../../../../docs/vocabulary/journey-flow-diagram.md) before changing anything here, then [JavaScript and JSX](../../../../docs/vocabulary/codegraph/languages/jsx.md#journey-flow-diagram) and [Vue](../../../../docs/vocabulary/codegraph/languages/vue.md#journey-flow-diagram) for what a component adds. The rules of [packages/codegraph/AGENTS.md](../../AGENTS.md) hold here too.

## Rules

- **A journey is drawn from chains.** `generateJourneyFromChains({ group, astGraphFiles, findComponentParts, scope })` returns one `JourneyFlow` for a segment, or `null` when no code that runs changed in it. `chain-facts.ts` turns the chains of the stored group into the facts the node builder reads: `traceChainFacts` starts at every top of `diffChains`, names its entry point, and walks `nextBlocks` down. A step that stays in the root block it is in stays in the node, a step into another root block is an edge between the two, and a step through a `root-argument-value` is no node: the prop it passes through is listed on the edge's `through`, and the place a handler is handed at is its `handedAt`. A prop on `through` is named `<component>.<prop>`, or `<component>.<event>` where the place the prop is handed at is an attribute site that carries an `event`, as a listener of a Vue template does: `CheckoutButton.checkout`. A node is a root block, read as the root encapsulation of the AST graph that starts on the same lines. Nothing is folded.
- **The top of a chain says its entry point.** A `render-event` is the user action of its attribute, a `code-event` a listener, an event bus or `Reached through <callback>`, a `component-effect` `<what it calls> runs` with the trigger `effect`, a slot the catalogue says runs as a page a visit of its path, a `route`, a `resolver`, a `middleware` or a slot that runs as one an API call named with its method and its path, a root block what `entryOfUnused` says, with a page visit for a component, and a statement at the root of a file the start of the app. A slot or a statement the diff did not touch has no node: its entry point leads to the first root block the chain enters. A named function in a component that nothing calls is `Not used yet`, on a node of its own.
- **A kept result carries where it was used.** A step from a declaration that keeps the result of a call to a callback of that call is a `value` edge that is `assumed`, with `usedAt` at the use that led to the declaration and `keptAt` at the call, so the node builder draws it from the handler that used the result, or absorbs it into the data of a component that read it in its markup.
- **A node is named by its block where the two differ.** `siteOf` in `chain-facts.ts` gives a site the name of its root block when the root encapsulation that holds it has another, as the component of a Vue file has: the block is `Cart` and the encapsulation `default`. Such a site is a component when its block holds a `render-root`. `nameOfSite` and `codeSiteIdOf` in `facts.ts` read the name, so the node, its id, its handler nodes and its parts all carry it.
- **A user action is read from the blocks where no syntax site says it.** A `render-event` with no attribute site, as in a Vue template, is the user action of its own name on the element of the block that holds it.
- **A function a pattern names as a route is a node behind its API call.** A callable block at the top of a chain keeps its node whether the diff touched it or not, so a Python function under a route decorator and a route export of a file are drawn.
- **A walk is told apart by the use it came through.** Two handlers of one component that reach the same declaration are two walks, so each click has its entry point and its handler node.
- **A changed node of the shared segment says so.** A Code Node has `isShared`, `true` for a changed node of a file of the shared segment that the journey of an entry segment passes through. `journey/build.ts` writes `Shared · Modified` or `Shared · Added` as its change label. A journey takes its id and its title from its own changed nodes, and from the shared ones only when it has no other, so the journeys of two lines under one shared file differ.
- **An entry segment keeps its own paths.** `scopeChainFacts` in `scope.ts` keeps the edges and the entry points that lead to a changed root block of the segment's files, and the edges below those that lead to a change of the shared segment.
- **A node nothing joins is left out.** `drawJourney` keeps a Code Node only when an edge or a trigger joins it, or when it reads changed data, so a component whose only change is in a handler is not drawn beside the handler node.
- **`listJourneyPaths` in `paths.ts` gives every path of a diagram as a line**, from its entry point to its last node, for comparing two diagrams.
- **An entry point carries where the trace ended.** An `EntryFact` has an `end`: the file and the range of the block at the top of the chain, with the event, the element and, for a component imported from outside the repository, the import specifier (`findExternalImportSpecifier`). `drawJourney` stores it as the node's `traceEnd`, with the line and its source. The entry point of changed bare statements has none.
- **A user action leads to a node for its handler, not to the component.** `drawJourney` gives every entry point with an `actedAt` (a handler attribute, or a listener inside an encapsulation) a Code Node of its own. Its ranges are the attribute or listener and the functions declared in the component that run at it; an edge whose use lies in those ranges leaves from the handler node, and the trigger edge arrives at it. An edge to the result of a hook is one fact per use of the result (`keptAt` is the call that keeps it), so a result used in a handler leaves from the handler node and a result read in the body from the component. Where the handler runs a prop, the node moves to the component that hands the handler over (`handedAt` on the edge, set where the trace follows a prop): the entry point then leads to `CartPage.handleCheckout`, and the trigger edge's `through` lists `Button.onClick` and the props between. A handler node is named `<component>.<handler or attribute>`, has the id of its component with the event and the line, is changed when a changed line overlaps its ranges, and its `tracedLines` are the element acted on and the handler. A component is a changed node only when a changed line lies outside every handler range that spans more than one line.
- **An entry point with no node under it is left out.** `drawJourney` keeps an Entry Point Node only when its trigger edge arrives at a node that is drawn. An entry point with one Code Node under it and nothing else is a path and is drawn.
- **A component is the only `ui` node, a handler node or the node of a callback an `event` node, and the node of an effect the only `effect` node.** `toDeclarationNode` in `journey-flow-diagram/index.ts` gives `ui` to a root encapsulation that `isComponent` of `entry-points.ts` accepts (a capitalised name or a default export, with markup inside) and `logic` to every other encapsulation: a function, the top level of a file, a constant that holds markup. `toActionDeclarationNode` gives `event` to every handler node, and `effect` to the node of an entry point with the trigger `effect`. The three are `GENERATED_NODE_CATEGORIES` in `packages/configurations`: the backend's `amend-journey.ts` refuses an agent's edit that writes or replaces one, and the playground's `written-parts.ts` keeps the generated one over a snapshot's.
- **A node says how it stands to the diff with `changeType`.** A Code Node is `diff` when a changed line is on it and `related` otherwise, since an unchanged node is only drawn on the way to a change; it is never `none`. `isChanged` is left on a traced line only.
- **A value read in markup is absorbed into the component's data.** In `drawJourney`, an edge is a data read (`isDataRead`) when it leaves a component, its use is one of `listDataReads` of that component, and it arrives at an encapsulation of the kind `variable` or is the read of a hook's result (`keptAt` is set). A site at least one data read arrives at, that every other edge into is the read of a hook's result by a component (`isAbsorbable`), that no entry point leads to and that no edge leaves from is in `listAbsorbedSiteIds`: it gets no node and no edge. A handler node that is unchanged and has no edge left is dropped with its entry point (`leadingActions`). The read is `related` in the component's `data` when the site is changed, and a diagram whose only change is absorbed is headed by the components that read it. `journey/filter.ts` treats such a component as a head.
- **A `ui` node lists its events and its data.** `journey-flow-diagram/traced-names.ts` reads them from the syntax sites and the value references inside the component: `listTracedEvents` gives one entry per callback attribute (an `on…` name, a function written in place, or a function declared in the component) and per `addEventListener` argument, and `listTracedData` one per variable read inside a `markup` site, without element names, plain callees, variables declared inside the markup and what lies in a callback attribute. An attribute site that carries an `event`, as a listener of a Vue template does, is named after it, `button.click`, and its handler node `<component>.click`. An entry is `{ name, changeType, reference }`, where `reference` is a line tuple and `changeType` is `diff` when a changed line is on the entry, `related` when one is on the function declared in the component that an event hands over or on the declaration statement of a variable inside the component, and `none` otherwise. The link never leaves the component. An entry of `events` also carries `nodeId`, the id of the drawn handler node whose ranges hold the attribute or the listener, or `null`. Every other node has both lists empty.
- **A component with several returns lists them.** `journey-flow-diagram/component-returns.ts` reads the `return` statements of a component's own body from its statements: it descends through conditionals, loops and `try` blocks, and never into a declaration, an expression or markup, so a `return` of a nested function or a callback is not one. With two or more, `listComponentReturns` gives one `ComponentReturn` each, in source order: an id (`<node id>#return@<line>`), the `statement` (the first line up to and including `return`, or the text of a return that is not written with `return`, as the directive of a branch of a Vue template is), its lines, `diff` or `none`, the traced lines up to the end of the return, and `renderedNodeIds`, the nodes of the render edges whose use lies in the return, in reading order. A component with one return, and every node that is not a component, has `returns` empty.
- **An Entry Point Node says what triggers the path.** `journey-flow-diagram/entry-points.ts` holds the triggers and their labels: `page-visit`, `user-action`, `api-call`, `command`, `boundary`, `effect`, `app-start` and `unused`. Every path has one. A changed handler written in place on a built-in element gives its handler node a user action of its own.
- **A node carries its traced lines, and an edge carries none.** `journey-flow-diagram/traced-lines.ts` lists the source lines a debugger would step through in a root encapsulation: a statement on the way with every line it spans, a branch, a loop or an inner function the path does not go into by its first lines only, no import and no type, and nothing after the target. In a JSX file an element is a statement of the type `markup`, nested under the element that holds it, so the lines step into the elements above a hand-over and stop at it. A node's `tracedLines` run to its changed lines, or to where the path leaves it when the diff did not touch it. They are how the inside of a node is shown without more nodes: a branch or a `.map` of a component is lines of that component. Changed bare statements at the top level of a file are one node named `top level`, whose traced lines are those statements. A changed import or type gives no node.
- **A node says which code is read beside it.** `journey-flow-diagram/code-views.ts` gives every Code Node and every return of a component its `codeViews`: a `kind`, a `path`, the `lines` as line spans, the `marks` as single-line column spans in reading order and an `entryCount`. A node that is not a component has one `declaration` view of its whole root encapsulation, and the top level of a file one of its changed statements. A component has a `data` view per file a value it reads in markup is declared in, with a mark on the declared name; one `event` view of every callback attribute and listener, each from the line its element starts on to the end of the attribute, with the functions the component declares for it and a mark on the attribute; and one `render` view of its `return` statements, or of the whole component when it has none. A return has the `data` and the `event` views of what lies on its lines, then its own `render` view. A handler node has one `event` view of its attribute and the handlers run at it. `journey-flow-diagram/return-statements.ts` lists the `return` statements both the returns and the views read.
