# packages/codegraph/src/ast-graph

The syntax of one file: what it declares and uses, its statements, and where a changed line belongs. Read [AST graph](../../../../docs/vocabulary/codegraph/ast-graph.md) before changing anything here. Each language has a guide of its own: [typescript](languages/typescript/AGENTS.md), [jsx](languages/jsx/AGENTS.md), [python](languages/python/AGENTS.md) and [vue](languages/vue/AGENTS.md). The rules of [packages/codegraph/AGENTS.md](../../AGENTS.md) hold here too.

## Rules

- **A file of the AST graph is built once, from its syntax.** `src/ast-graph/languages/base.ts` holds `ASTGraphFile`, one class for every language. Its constructor takes the path of the file, `diffLines` and a `FileSyntax` of `types.ts`: the source lines, the root encapsulations, the variables, the import variables, the references, the export aliases, the re-exports, the syntax sites and the statements. Nothing changes them afterwards. It places `diffLines`, the line ranges the change touches in the file, as `DiffLocation`s: a range of changed lines, the root encapsulation it lies in and the nearest encapsulation that holds it. A location belongs to one root encapsulation, so a range that spans several, such as the whole of a new file, is split into one location per root encapsulation and cut to its lines. Changed lines outside every root encapsulation have no location.
- **A language reads the syntax of a file, and nothing here parses.** `languages/<language>/index.ts` holds `readTypescriptSyntax`, `readJsxSyntax`, `readPythonSyntax` and `readVueSyntax`: each takes a parsed tree and the files its imports resolve to, and returns a `FileSyntax`. The language of the code blocks calls it with the tree it read the blocks from, when the syntax is first asked for, so a file is parsed once. `listASTGraphFiles(syntaxByPath, diffLinesByPath)` in `definition.ts` builds the files of a group from what `readCodeGroup` of `code-blocks/` keeps.
- **An encapsulation without a name of its own is traced through the one that holds it.** A method is not a variable, so its uses are the uses of its class, and its node is named `Class.method`. A root encapsulation is known to importers by its own name and by every export alias of that name: `default` for `export default function priceOf`, `price` for `export { priceOf as price }`.
- **A name is handed on only where it is exported.** A file hands an imported symbol on under the names it exports that import by, and under the names of its re-exports: `export { a as b } from`, `export * from`, which keeps every name but `default`, and `export * as ns from`. Python exports every name it imports. A namespace import counts as a use of a symbol only in a file that imports the symbol's own file, not one that reaches it through a re-export.
- **A name is resolved once per space.** A declaration and a use each carry the spaces they live in, `value`, `type` or both, so `const Cart` and `type Cart` in one scope stay apart. A use belongs to the declaration of its name with the nearest scope in each of its spaces, and to every such declaration when several share that scope. A class, an enum, a namespace and an import are in both spaces.
- **An encapsulation is something a changed line can belong to.** At the root of a file that is a function, a class, a variable, an enum, a namespace or a default export. Below the root it is a function, a class, a method, or a variable, field or member of a declared object that holds a function or a class. Types, declarations marked `declare`, overload signatures and the members of an object handed to a call or to an element are not encapsulations. An object handed to `defineComponent` is the exception: its members are.
- **A name is looked up once, for the views and for the page.** `ast-graph/definition.ts` holds `findDefinition(files, file, target)`: a name declared in the file leads to the lines of its root encapsulation, or of the narrowest `import`, `type` or `declaration` statement that holds it, or to its own line for a parameter; an imported name leads to the lines the file it comes from exports it by, through re-exports, and to its import statement when it comes from a library, from a namespace import or from a file outside the group. `generateCodeReferences(astGraphFiles, paths)` in `code-references/` lists, for each path, every single-line use with its columns, the `path` and `lines` of its definition and `isLibrary`, and leaves out a use that lies on the lines of its own definition. `buildCodegraph` asks it for the files of the Code Walkthrough and of the journey nodes, and a segment carries the result as `codeReferences`.
- **A file answers its syntax sites and its statements.** `syntaxSites` of a `FileSyntax` holds the attributes, arguments, callees, members, elements, functions and kept values of a file as `SyntaxSite`s, and `statements` its statements nested with their arms. `languages/typescript/syntax-sites.ts` and `statements.ts` read them, `languages/jsx/syntax-sites.ts` adds the element sites, and `languages/nest-statements.ts` nests statements and arms by what contains what. A Vue file gives what a JSX file gives, read from its template and its script blocks: see [languages/vue/AGENTS.md](languages/vue/AGENTS.md). Python gives its statements, read by `languages/python/statements.ts`, and no syntax sites.
- **Every parse goes through `ast-graph/parser.ts`.** It parses with the native `tree-sitter` package and the `tree-sitter-typescript`, `tree-sitter-python` and `tree-sitter-html` grammars, keeps one parser per grammar and the compiled queries, and is the only module of `ast-graph/` and `import-graph/` that holds state. Parsing is synchronous and a tree is freed by the garbage collector.
- **A tree is walked with a cursor.** `ast-graph/walk-tree.ts` holds `collectFromNode`, which visits the nodes under a node through a tree-sitter `TreeCursor`. Code in `ast-graph/` walks with it, never with a recursive read of `children`.
