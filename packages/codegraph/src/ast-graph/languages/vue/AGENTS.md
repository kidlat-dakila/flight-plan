# packages/codegraph/src/ast-graph/languages/vue

How a `.vue` file is read. Read [Vue](../../../../../../docs/vocabulary/codegraph/languages/vue.md) before changing anything here. The rules of [ast-graph/AGENTS.md](../../AGENTS.md) and of [packages/codegraph/AGENTS.md](../../../../AGENTS.md) hold here too.

## Rules

- **A Vue file is three languages, parsed once.** `parseVue(source)` in `parsed.ts` parses the whole file with the `html` grammar (`tree-sitter-html`), each script block with the TypeScript grammar its `lang` names, and the expressions of the template as one text of TypeScript. A script block and the expressions are parsed as the file with everything else blanked (`blanked.ts`), so every position of a tree is a position of the file. `sfc.ts` finds the script blocks and the template. `expressions.ts` writes every expression where it stands (an interpolation, a bound attribute, a handler, a `v-for`, the properties of a slot) and says which ranges declare names. `readVueSyntax` reads the lists of a file from a `ParsedVue`, and the language of the code blocks reads its blocks from the same one. `template.ts` reads a name written in a declaring range as a variable seen inside its element, and every other name as a use.
- **A Vue component is the default export.** A `<script setup>` block and the template are together one root encapsulation named `default`, from the first line of the first to the last line of the last, with the functions the script declares inside it, and a file that does not export a default declares the variable `default`, so an importer's default import leads to them. The top level of a setup script is seen by the template, the top level of a script without setup is not. A `v-for` variable and a slot property are seen inside their element only. A capitalised tag, a tag with dashes and the object of a member tag are uses of the component's name, and `v-focus` is a use of `vFocus`.
- **A Vue file gives the journey what a JSX file gives it.** `readVueSyntaxSites` in `syntax-sites.ts` gives an `attribute` site for every `@event` and `v-on` handler and every bound attribute of the template, an `element` site for the tag of every component, a `markup` site for the template and for each element, and the sites of every script block and of every expression of the template, each moved to its place in the file. An attribute site of a listener is named as its listener, `onClick`, and carries the `event` as it is written, `click`. `readVueStatements` in `statements.ts` gives one `declaration` statement for the component, which holds the statements of the setup script and the template: a `return` for the template with its elements nested as `markup` statements, or a `return` for each branch of a `v-if` chain at its root, whose text is the directive. The statements of a script without setup are at the top level of the file. Nothing in `journey-flow-diagram/` asks whether a file is a Vue file.
- **`markup.ts` reads a tag and an attribute.** It says which attribute is a listener, a bound attribute, a condition, a loop or the properties of a slot, and the name each is handed under. The code blocks of a Vue file read it too.
- **Vue says with its own syntax what JSX says with attributes.** An emitted event is a prop: `@save` on a component is followed into that component, to where `emit("save")` or `$emit("save")` runs. `provide(key, value)` is a `Provider` value and `inject(key)` its reader. The top level of a `<script setup>` block and the template are the render body, and a function declared at that top level is a function declared in the component. The branches of a `v-if`, `v-else-if`, `v-else` chain at the root of the template are the returns of the component.
- **A Vue component is a `ui` node named after its file.** `Cart.vue` is `Cart`. A handler node is named `<component>.<handler>`, or `<component>.<event>` for an expression written in place, an entry of `events` is `<element>.<event>`, and an event a component emits on is `<component>.<event>` on the `through` of a trigger.
