# packages/codegraph/src/journey

The band of a Journey Flow Diagram: what the review page receives. Read [On the page](../../../../docs/vocabulary/journey-flow-diagram.md#on-the-page) before changing anything here. The rules of [packages/codegraph/AGENTS.md](../../AGENTS.md) hold here too.

## Rules

- **The band has no positions.** `buildJourney(segment, scope, places, context)` in `build.ts` turns the nodes of a segment's diagram into `JourneyNodeView`s, nested as the nodes are, and the edges into their ids and their two ends. `packages/ui` places them.
- **A node view is words and code.** It carries the `type` and its label from `BLOCK_TYPE_LABELS`, the written label or the name of the code as a draft, the `name` of the code, the `shortPath` of the file, which is its last two folders and its name at most (`routes/orders/index.tsx`), the description as prose, and `change`: `added` when every line of the block the node stands for is new, `modified` when the node has another change, `null` when it has none.
- **A block is named in one place.** `nameOfBlock` in `names.ts` gives the name of a block, the name the catalogue gives it, or its type and its line. A call is named after the `binding` of its symbol when it has one, so a hook taken from a declaration of several names is named after the one imported. A block the catalogue says is a node of its own is named after the key it is written under, `list` of a tRPC router. An effect with no name is named after what it calls, `useMutation`. A `render-event` is named after its element and itself, `button.onClick`. A member read from an argument is named after the argument and itself, `props.onSave`. The band, the code links and the backend's node tools all read it.
- **Each card groups its rows as `cards/` says.** `listRowGroups` in `cards/index.ts` gives a node its `rowGroups`, each a label, the ids of its rows and the ids of the children drawn under it (`childIds`), which is the order the page draws them in. `cards/component.ts`: the groups Args, State, Hooks, Effects, one per label of its calls, Triggers and Steps, for a `component` and for a `function`, a `hook` or a `method` that returns a function. `cards/class.ts`: the rows that are no property in the order they are written, then Properties, then Methods with the method children as `childIds`. `cards/function.ts`: any other node, one group with no label, its arguments first and every other row and trigger label in the order it is written. `cards/route.ts`: a route node lists no row, and puts each handler under the heading of its method, POST, PUT, PATCH, GET, DELETE, HEAD, OPTIONS, then a heading of several methods (`GET · POST`), then ANY, a heading that names a version (`GET v2`) after the heading of its method alone, headings of one rank in order (`compareHeadings`). `cards/router.ts`: a router lists no row, puts each procedure under Query, Mutation, Subscription or Field, and a child with no heading (a method of a NestJS resolver that resolves nothing) under Methods. `cards/store.ts`: a store puts its `part` rows and its children under the heading of their part, in the one order of `STORE_HEADINGS` every state library shares, and any other row after them with no label. `cards/headed-children.ts` puts the children of a node under the heading in their `card`. A child no group names, such as a rendered component or a class that extends another, is drawn after the groups. `cards/labels.ts` holds the labels of the kinds, and `labelOfHeading` turns a heading of a card, `EXTRA REDUCERS`, into the label of a group, `Extra reducers`. `blockLists` holds the rows by kind and is no order.
- **Some cards head differently.** `headOfNode` in `cards/index.ts` gives the name and the type label of a node's head: a route node is named after its path and reads Route, a router reads Router, a router whose node is a class (a NestJS resolver) reads Resolver, a class with a `controller` card reads Controller, an RTK Query API reads API, a server action (a `route` card of the part `server-action`) reads Server action, and every other node is named after its block and reads the label of its type. `listsNoRows` says which nodes list no row at all: a route and a router.
- **A trigger of an event handed a function has the lines of that function too.** `linesWithHandlers` adds them, `hasChange` marks the trigger when the function changed, and `codeLinesOf` gives the node of the event the lines of the function as its code.
- **A node lists its arguments, its state, its hooks, its effects, its calls and its steps.** `toBlockLists` in `build.ts` reads the listed blocks of a node from `listListedBlocks` of `journey-flow-diagram/listed-blocks.ts`, gives each the label of its `blockLabels` entry, or the name of its code as a draft, and gives one `blockLists` entry per kind that has a block, in the order `argument`, `property`, `state`, `hook`, `effect`, `call`, `step`, `part`. A hook is an `external-value` with a call of a name that starts with `use` and a capital letter, listed under that name. An effect inside a `state` or a `derived` declaration of the node is listed as that declaration, under `state`, whether or not a chain passes through the declaration. A step is any other block that `isStepBlock` names, that is a node of its own or that has a change, but an event, a data fetch, markup and a function written in place of an event or a callback. What is inside a listed block is folded into its row, and the statements that follow each other are one step, as [Steps](../../../../docs/vocabulary/journey-flow-diagram.md#steps) says.
- **A row carries the lines of its block.** Each listed block and each trigger label has `lines`, the line spans of its block, so the page can focus the code of the node on them. A step of several statements has one span, from the first line of the first to the last line of the last.
- **A row is changed when its block is, or the function written in place of it, or a block folded into it.** `changeOfBlock` marks an event whose arrow function changed, and `toBlockLists` marks the row `rowIdAround` gives each changed block of the node.
- **A line leaves the row of the block that takes the step.** `rowIdByBlockIdOf` gives every statement of a step the id of its row, and `rowIdAround` the row of a block or the nearest one around it. `toEdgeViews` gives an edge one view per step between its two nodes (`listNodeSteps` of `journey-flow-diagram/node-blocks.ts`), and one from the row of an inner node's block to the head of that node. A step that leaves the block of a node, or reaches it, has no row on that side.
- **A node shows the code of its block.** `buildNodeCodeViews` in `code-views.ts` gives a node one view of the lines of the block it stands for, and of every folded value it holds (`codeLinesOf`), read from the source as the Code Walkthrough reads it, with a `waypoint` row above the first line each waypoint covers (above the first line shown when the waypoint starts earlier) and a note for a file outside the segment's `changedPaths`. `listWaypointPlaces` in `walkthrough/build.ts` gives the visible waypoints with their ranges, and the caller hands them to `buildJourney`.
