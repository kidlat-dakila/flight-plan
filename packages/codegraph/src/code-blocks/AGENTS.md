# packages/codegraph/src/code-blocks

The blocks of every file of a group, what each block uses, the block around each change, the chains that lead to a change, and the segments of a group. Read [codegraph](../../../../docs/vocabulary/codegraph.md), then the page of what you touch: [code blocks](../../../../docs/vocabulary/codegraph/code-blocks.md), [block types](../../../../docs/vocabulary/codegraph/block-types.md), [symbols](../../../../docs/vocabulary/codegraph/symbols.md) and [chains](../../../../docs/vocabulary/codegraph/chains.md). The rules of [packages/codegraph/AGENTS.md](../../AGENTS.md) hold here too.

## Rules

- **This folder is what the codegraph is built on.** It reads `import-graph/`, the parser and the readers of `ast-graph/languages/`. `buildCodegraph` builds the groups of a change with `readCodeGroups`, cuts each with `cutSegments`, and draws each segment from its group. The shapes here are named as the pages name them, `ASTGraph` and `ASTCodeGroupGraph`. `src/index.ts` exports the functions, the stored shapes, and `CodeBlock`, `CodeBlockSymbol`, `CodeBlockType`, `CodeBlockCatalogue` and `DiffKind`.
- **A group is built as its stored form, then linked.** `buildStoredCodeGroupGraph(files)` in `build-group.ts` is a calculation from the files of a group, each with its source, its importers and the ranges of its changes, to a `StoredCodeGroupGraph`: plain data in which every reference is an id or a file path. `linkCodeGroupGraph` in `link-group.ts` turns it into the `ASTCodeGroupGraph` the pages describe, where every reference is the same object, and `storeCodeGroupGraph` in `store-group.ts` turns a group back. A reference in memory is a getter that looks its block up once, so nothing is mutated to close a cycle. Snapshots and comparisons read only the stored form.
- **A file is read once, and its syntax is kept beside the group.** The `read` of a language returns the blocks and the uses of a file, and `readSyntax`, which reads the `FileSyntax` of `ast-graph/` from the tree the blocks were read from. `readCodeGroup(files)` in `build-group.ts` returns the stored group and `readSyntaxByPath`, which reads the syntax of every file of the group the first time it is called. The syntax is not part of the stored form: it holds no reference, and it is what the diagrams read the inside of a node from. `buildStoredCodeGroupGraph` is the stored group alone, and `readCodeGroups` in `read-groups.ts` reads every group of a change with its syntax.
- **A symbol is stored by where it is held.** A symbol has no id, so `handedFrom` of a block and `externalSymbols` of a file hold a `StoredSymbolPlace`: the id of the block that holds the symbol and its index in that block's `outerSymbols`.
- **A value handed under a name goes to the argument of that name.** `findArgument` in `link-references.ts` hands a value written under a key to the key of the first argument, to a member read from it, or to the whole argument of that name, as a Python keyword argument is.
- **`readCodeGroupGraphs(change)` is the only part that reads.** `read-groups.ts` traces and clusters the import graph, splits each cluster with `splitIntoGroups`, reads the sources with one `blobs` call per commit and the changes with `diffsOf`. A changed file in no cluster, such as a migration, is a group of its own. A deleted file has no ranges.
- **A test and a story are in no group.** `isIgnoredFile` in `ignored-files.ts` reads which files they are from the catalogue: every file pattern of `BUILT_IN_LIBRARIES` that says `isIgnored`, which `libraries/javascript/testing.ts` and `libraries/python/testing.ts` hold. `listIgnoredGlobs` and `isIgnoredBy` do the same for any list of libraries. `splitIntoGroups` in `group-files.ts` takes them out of a cluster, splits what only they joined, and drops the files that no longer lead to a change.
- **The range of a change has columns.** `diffsOf(patch)` in `patch-ranges.ts` gives each change as a diff, with its range and its type: `added` for lines that were only added, `deleted` for lines that were only removed, `modified` for any other run. It pairs a run of removed lines with the same number of added lines and gives what each pair does not share. A line that is only added is its text without the blanks around it, and a blank one gives no range. Lines that were only removed are a position with no width on the line that took their place. Lines and columns start at one, and the end of a range is the column after its last character.
- **A language reads a file in two steps.** `languages/index.ts` picks the language by extension. `outlineFile` reads what a file declares and exports, and its `read(findExport)` makes the blocks and the uses, once `createExportTable` in `export-table.ts` can answer what a name of another file leads to: a callback passed by name counts only when the name leads to a function. A file no language here reads, or one that holds no block, is one `file` block that spans it.
- **TypeScript and JSX share one language.** `languages/typescript/blocks.ts` walks the tree with a cursor and makes the blocks, `calls.ts` says what a call, a `new` or a member read is (an effect, a listener, a global of the platform), `markup.ts` says what is markup, `arguments.ts` makes the `root-argument-value` blocks, `uses.ts` says how each name is used, `written-at.ts` says where a value is written (its attribute or its argument, and the keys of the object it is in) and under which keys a function of an object is, and `outline.ts` resolves every name once with the readers of `ast-graph/languages/typescript/`. `readScript` reads the blocks and the uses of one script, at the root of a file or, when it is handed the id of a component, as the body of that component.
- **Python is read by its statements.** `languages/python/outline.ts` resolves every name with the readers of `ast-graph/languages/python/`, and `blocks.ts` walks the tree with a cursor: an `import`, a `function` from its first decorator, a `method` named after its class, a `class`, a `root-variable`, a `root-statement` around every other statement at the root, a `condition`, a `switch` with its `switch-case` blocks, a `loop`, a `try-catch`, a `throw`, an `external-value` below the root, and a `root-argument-value` per argument of a root function or of a method of a root class, without `self` and `cls`. A `with`, a name bound in the body of a class and a plain local are no blocks. A function carries what the catalogue says of its decorator, and a call a pattern names is a block of the type the pattern makes. `uses.ts` says a name is called, read through a member, handed over by position or by keyword, or named in an annotation, and reads a member of `self` or `cls` that names a method of the class around it as a use of that method, which is declared at its name. A member that is called and names no method of that class is a use of each class it names as a base, with that member, and `followMembers` finds the method. A member that is only read is no use of a base. A file exports every name its root binds and every name it imports.
- **A Vue file is one component.** `languages/vue/index.ts` makes one `component` block that spans the `<script setup>` block and the template, named after the file, and it is the default export. The file is parsed once by `parseVue` of `ast-graph/languages/vue/`, and its trees serve the blocks and the syntax. The setup script is read by `readScript` as the body of that component, from the tree of the file with everything but the script blanked, so every position is a position of the file. An `import`, an `interface` and a `type` at the top level of the script are blocks at the root of the file, not inside the component (`isModuleWide` in `languages/typescript/blocks.ts`), so a change of an import is placed in the import. `template-blocks.ts` makes the `render-root`, a `render` per element, a `render-condition` for `v-if`, `v-else-if`, `v-else` and `v-show`, a `render-loop` for `v-for` and a `render-event` per listener. `template-uses.ts` reads the tree of the expressions of the template, each written where it stands, and resolves its names against what the setup script declares and imports and against the props, without the names an element declares itself. `component-arguments.ts` makes a `root-argument-value` per prop of `defineProps` and per event of `defineEmits`, named as its listener (`onSave`), reads `props.title` as a use of the prop and `emit("save")` and `$emit("save")` as a call of the event. An emit that is the whole value of a listener on a component of the repository is the event as a `value`, handed to the event listened for (`findHandedPlace` of `template-uses.ts`). The whole value of a bound attribute or of a listener on a component is handed to the prop or the event of that name. A `<script>` block without `setup` is read as a TypeScript file at the root. In a file with no `<script setup>`, `options.ts` lists the members of `methods` and of `computed` and the keys of what `data` returns, in the object that script exports as its default or hands to `defineComponent`, and the template resolves its names against them: the block of a member is declared at its key. It also lists the `props` and the `emits` of that object, each a `root-argument-value` of the component, reads `this.$emit("save")` as a call of the event, and reads a member taken from `this` in a function of that object as a use of the member, the key or the prop of that name (`listReceiverUses`). A `this` under a second function written with `function` is not read.
- **The id of a block is derived.** `blockIdOf` gives the file path, the type and the start, such as `src/page.tsx#function@12:1`. Two blocks of one type that start at the same place, as the calls of `bus.on(…).on(…)` do, are told apart by the end of the inner one.
- **References are filled in after every block exists.** `linkReferences` in `link-references.ts` holds each use in the innermost block around it, leaves out a name declared inside that block, and turns an import into a block through the export table. It fills `usedBy`, `handedFrom`, the `exports` of each file and `exportedBy`.
- **A change belongs to the innermost block around it.** `placeDiffs` in `diff-blocks.ts` nests the ranges of the blocks of a file and descends to the innermost one that holds a change. A range that crosses the edge of a block is cut at the edge, and each part belongs to the innermost block around it. A change outside every block belongs to the root block that follows it, or to the last one.
- **A name declared below the root is a `variable`, and a key that holds a value a `property`.** In `languages/typescript/blocks.ts` `readDeclarator` makes a `variable` of a local declaration no other type claims, `readBound` of an argument of a function below the root, of a name a `for … of` binds and of a caught error, and `readOption` and `readField` a `property` of a key and of a field that is no function. `languages/python/blocks.ts` does the same for a local assignment, an argument of a nested function or a lambda, the target of a `for`, an attribute of a class, the first `self.name = …` of a class, and a key of a dictionary written as text. `languages/python/members.ts` lists the attributes of a class and reads the key path of a dictionary, and `uses.ts` reads `self.name` and `CONFIG["key"]` as members, and gives a second use, a read of the key, for `CONFIG.get("key")` of a name the group can open. In TypeScript `class-members.ts` lists the members of a class, the ones first set through `this` among them, for `readAssignedMember` in `blocks.ts` and for the receiver uses. An argument block is marked `isParameter`, so it holds no block that follows it. `findWrittenMember` and `findMethod` in `value-origins.ts` lead a member to a property as they do to a function.
- **Code that was taken out is a `deleted` block when it stands alone.** `diffsOf` keeps the removed lines of a change that only removed lines. `listDeletedCode` in `deleted-blocks.ts` reads them with the grammar of the file (`grammarOfFile`), as members of a class when they were inside one, and makes a block with no width where they were: at the root for anything that parses, inside a block for a declaration only. `listRemovedDecorations` gives removed decorators to the block that starts on that line: lines are decorators when they parse above a class, a member or a function written after them and add no declaration of their own. `readCodeGroup` adds the blocks to the file after the other changes are placed, so no other change lands on one.
- **For the chains, a variable, a property and an argument change with their holder.** `sourceOf` in `chains.ts` climbs from one of the `OWNED_TYPES` to the block around it, `isHandlingBlock` reads a variable and a property as part of the handler they are in, and `runMemberOf` does not step to a property: a read of a key still leads to the value it is read from. A `deleted` block is among the `UNTRACED_TYPES`.
- **A block that uses a changed block is affected.** `traceAffectedDiffs` in `affected-diffs.ts` visits the files from the root files down the imports (`listFilesFromRoots`), and again from each file a loop of imports kept out of reach. It adds a diff of the type `affected` to `diffs` at each use of a block that has a change written in it or inside it. The used block is the member a symbol leads to when it has one, never a `root-argument-value`, and never the using block, a block around it or a block written inside it. A symbol whose member leads to no block is passed over when a wider symbol of the same name leads to one, and of two uses of one block the wider range is kept. It leaves `lineOfCodeDiffs` alone, so an affected block is not a diff block.
- **A member reached through `this` or `super` is a use.** `readReceiverUse` in `languages/typescript/uses.ts` gives a use of the method or the function field of the class a `this.name` is written in, and of the class it extends when the class has no such member or the receiver is `super`, for a call and for a read alike. A `this` inside a function with a receiver of its own gives none. Python does the same through `self`.
- **`diffContains` is read from the diff blocks.** `readDiffContains` in `diff-contains.ts` gives the kind of each diff block's type, and `ui` for a `component` block and for a block inside one, or inside any other function that has a `render-root`. A block of a type with no kind of its own, outside a component, is `logic`.
- **A chain steps where code runs.** `traceChains` in `chains.ts` lists, for every block, the blocks it runs next: the blocks nested in it that run with it, the block behind each symbol it calls or renders, the function written in place in an event, a callback or a loop of markup, the callbacks of an effect that keeps no result, and the methods of a class. A handler passed by name to an element or a call outside the repository is run by its event or callback. An argument block runs what each place hands it. A declaration that keeps the result of an effect is two steps apart: the block that holds the declaration steps to the call, and a use of the declaration steps to it and from there to the callbacks of the call. A declaration at the root of a file has no holder, so a use of it steps to the call too. `nextBlocks` is those steps that lead to a change, `diffSources` the changed blocks a block leads to, and a top is a block on a chain that nothing runs. A use of a value, a `root-variable`, a `state` or an `external-value`, steps to it whatever the use, and a function steps into an effect it returns. An element outside a `render-root` and outside a page slot is a `value`, not a `render`. A function passed by name to a method of a list or of a promise, `items.map(priceOf)`, is a `call`. An argument block starts no chain, and a changed argument is traced as a change of its function. A type, an import and a `file` block are never traced and take no step.
- **A use of a block declared inside the holder is a symbol.** `linkReferences` keeps a use of an argument, a function, an `external-value` or a `variable` declared inside it, since a chain steps through them and a change to one affects its readers. It leaves out a name the block declares that is no block.
- **A member a callback takes from a value is a use of that value.** In `useCartStore((state) => state.addItem)`, `uses.ts` reads `state.addItem` as a use of what was called, `useCartStore`, with the member `addItem`, when the callee is an import or a declaration at the root of the file. A function written in place in an `effect-callback` runs what it names, so a call of the kept result reaches the action. This is assumed: nothing proves the argument of the callback is the value.
- **A member is followed to the origin of its value, by its whole path.** `followMembers` in `value-origins.ts` runs after `linkReferences`, with what `linkReferences` kept of each use: where it is written (`writtenAtBySymbol`) and the keys of each function of an object (`memberPathById`). For a symbol with a member that names a value, `followPath` looks in that value for a function written under the keys the path starts with, the longest that fits, or else for a function of that name declared inside the value, as an action of a store written as a setup function is, then follows every name the value holds: a name under a key the path starts with, a name with no key, what an object spreads, what a function or a hook it calls returns, what a variable it calls holds, as `useCartStore` of `const cart = useCartStore()` does, the methods of a class it makes, and what a context provides. A method is looked up in the class and then in the classes it names as a base, nearest first (`findMethod`): a base is a use written as one, `isBase` of `WrittenAt`, which `extends` in TypeScript and the list after the name of a Python class set. A member of a symbol that names a class is found the same way. A use of a name taken apart in a declaration carries every key it was taken through, `const { orders: { remove } } = api`. A context is followed only where a call the catalogue names with `reads` is handed it at `reads.keyAt`, and what it provides is read from the place `provides.valueAt` names: the `value` attribute of the element of a factory with `provides`, as `createContext` of React has, or the argument of a call with `provides`, as `provide` of Vue. A context is also followed from an element the catalogue names as a reader: `uses.ts` reads a member the function written inside `<ThemeContext.Consumer>` takes from its first argument as a use of the context with the path `Consumer.<member>`, and `followThroughReader` follows the rest of the path through what the context provides. `linkReferences` itself sets `member.block` only for a member of an argument that is not taken apart.
- **`fetch` is a `data-fetch` when the call says it reads.** `typeOfCall` in `languages/typescript/calls.ts` makes a call to the global `fetch` a `data-fetch` when it has no options, or options written in place that name no method or the text `GET`, in any case. Options that are a name, that spread another object or whose method is a name make it a `request`. `typeOfConstruction` makes `new EventSource(…)` a `data-fetch`. Both count as `data` in `diffContains`.
- **A call that provides a value is no effect.** `typeOfHandedCall` in `languages/typescript/calls.ts` makes no block of a call a pattern names with `provides`, which `isProviding` of `named-by.ts` says, so a function handed to `provide(key, { toggleTheme })` is a `value` use, not an `effect-callback`.
- **An `effect` runs with the block that holds it, a `component-effect` that keeps no result starts a chain.** A function with no name written in place runs with its holder too, which is assumed. A call handed a callback inside the attribute of an event is an `effect`, not a `component-effect`: `blocks.ts` reads it as elsewhere once it is inside a `render-event`.
- **`chainContains` is read from the blocks on the chains**, by the same kinds as `diffContains`. No chain is traced when `diffContains` holds only `type` and `file`.
- **The catalogue names state.** `languages/typescript/made-by.ts` matches the call a declaration keeps against the call patterns of `BUILT_IN_LIBRARIES` that have `makes: "state"` or `"derived"`, through the import of the name or of the whole library, and the declaration becomes a `state` or a `derived` block with its `catalogue`. A match of `named-by.ts` that makes state does the same through the origin of what is called, so a declaration that keeps what a zustand store hands back, `const status = useOrderFilterStore(selectStatus)`, is a `state` block.
- **The catalogue names the other blocks through `named-by.ts`.** A file is matched once with `matchSyntax`, and `createFileNaming` answers by the range of a node. A call a pattern matched is a block of the type the pattern makes, or a `route`, a `resolver` or a `middleware` when it has a slot that runs as one, and keeps its syntax type otherwise. Its `catalogue` holds the specifier, the name, the path, the method and the event. A callback the pattern names is a block even when its name leads to no function, is a `code-event` when the slot runs on an event, and has `catalogue.runs`. A property a pattern names as a slot is a block at any depth of the options, as `element`, `Component`, `loader` and `lazy` of a route of `createBrowserRouter` are, each with the path of its route, and an element written in a slot that runs as a page is a `render`. An element, a class and a method keep their type and get the `catalogue`: a decorated method has the route of its decorator with the prefix of the decorator of its class before its path, and a method of a class that extends an export has what the class pattern says of that member.
- **A value is followed into the file that makes it.** `buildStoredCodeGroupGraph` hands every file a `findBinding`, which finds the declaration behind an export through the export table and asks the file that holds it.
- **A file pattern names the block behind an export.** `readStoredCodeGroupGraphs` reads every manifest of the repository at the head commit (`manifests.ts`: `package.json`, `pyproject.toml` and `requirements*.txt`), and each file gets the nearest one above it: the packages it lists and the path of the file from its folder. `listExportNamings` in `languages/file-catalogue.ts` matches that path against the file patterns of the libraries the manifest lists, and `withExportNamings` leaves what a pattern says of an export on the block behind it, with the path of a page or a route read from the folders of the file by `routePathOf`. The first pattern that names an export holds. A manifest lists a library under a specifier of the library or under a registry name the library list in `data/libraries.ts` gives it, so `django-allauth` is the library imported as `allauth`. A file with no manifest matches no file pattern.
- **A directive names the functions of its file.** `languages/typescript/directives.ts` leaves what a directive pattern says, such as `"use server"`, on every exported function of a file that starts with it, or on the one function that starts with it.
- **A route runs its handler.** In `chains.ts` the callbacks of a block the catalogue names are steps of that block, as the callbacks of an effect are.
- **A component is a block type.** `typeOfCallable` in `languages/typescript/blocks.ts` makes a function a `component` when it returns markup and is not written in markup, unless its name makes it a `hook`, and `readDeclarator` makes a variable that holds markup a `component` too, with the markup as its `render-root` and `holdsMarkup` on what was read. Both hold at any depth of a file. `traceChains` in `chains.ts` is handed the ids of the blocks that hold markup: such a block runs with the block that declares it and is reached by any use of it, as a value is, where a component that is a function is reached only where it is called or rendered.
- **A group is cut into segments here.** `cutSegments` in `segments.ts` reads which file uses which from the symbols, makes a changed file shared when two files use it or when it leads to two lines of change below it, through unchanged and shared files, and joins every other changed file to the one line below it. `listBlocksUsing` gives the blocks that hold or use a changed block of some files, directly or through other blocks, and `listReachedFilePaths` the files among them the diff did not touch.
- **A file says what its own diff holds.** `diffContains` of an `ASTGraph` is read from the blocks of that file alone.

## Layout

```
types.ts            the shapes in memory: a group, a file, a block, a symbol
stored-types.ts     the same shapes with every reference as an id or a file path
reading.ts          what a language hands back: blocks, uses and exports
build-group.ts      the files of a group → its stored form
link-group.ts, store-group.ts  the stored form → the group in memory, and back
read-groups.ts      a change → its groups, read through git-forge
group-files.ts, ignored-files.ts  the files of a group, without tests and stories
patch-ranges.ts     a patch → its changes, each with a type and a range with columns
export-table.ts     a file and a name → the declaration behind it, through re-exports
link-references.ts  the symbols of each block, and every reference between blocks
diff-blocks.ts, diff-contains.ts  the block around each change, and the kinds of change
affected-diffs.ts   the blocks that use a changed block
deleted-blocks.ts    the blocks of code a change took out
chains.ts           what each block runs next, the changed blocks it leads to, and the tops
value-origins.ts    where a value comes from, and the function behind a member of it
segments.ts         the entry segments and the shared segment of a group, and the files a change reaches
source-range.ts     positions and ranges
manifests.ts        the manifests of a repository, and the one nearest above a file
languages/          the registry, typescript/ for TypeScript and JSX with named-by.ts for what the catalogue says of a block, python/, vue/, and file-catalogue.ts for what the path of a file says of its exports
```
