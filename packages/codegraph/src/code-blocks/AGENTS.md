# packages/codegraph/src/code-blocks

The blocks of every file of a group, what each block uses, the block around each change, the chains that lead to a change, and the segments of a group. Read [codegraph](../../../../docs/vocabulary/codegraph.md), then the page of what you touch: [code blocks](../../../../docs/vocabulary/codegraph/code-blocks.md), [block types](../../../../docs/vocabulary/codegraph/block-types.md), [symbols](../../../../docs/vocabulary/codegraph/symbols.md) and [chains](../../../../docs/vocabulary/codegraph/chains.md). The rules of [packages/codegraph/AGENTS.md](../../AGENTS.md) hold here too.

## Rules

- **This folder is what the codegraph is built on.** It reads `import-graph/`, the parser and the readers of `ast-graph/languages/`. `buildCodegraph` builds the groups of a change with `readCodeGroups`, cuts each with `cutSegments`, and draws each segment from its group. The shapes here are named as the pages name them, `ASTGraph` and `ASTCodeGroupGraph`. `src/index.ts` exports the functions, the stored shapes, and `CodeBlock`, `CodeBlockSymbol`, `CodeBlockType`, `CodeBlockCatalogue` and `DiffKind`.
- **A group is built as its stored form, then linked.** `buildStoredCodeGroupGraph(files)` in `build-group.ts` is a calculation from the files of a group, each with its source, its importers and the ranges of its changes, to a `StoredCodeGroupGraph`: plain data in which every reference is an id or a file path. `linkCodeGroupGraph` in `link-group.ts` turns it into the `ASTCodeGroupGraph` the pages describe, where every reference is the same object, and `storeCodeGroupGraph` in `store-group.ts` turns a group back. A reference in memory is a getter that looks its block up once, so nothing is mutated to close a cycle. Snapshots and comparisons read only the stored form.
- **A file is read once, and its syntax is kept beside the group.** The `read` of a language returns the blocks and the uses of a file, and `readSyntax`, which reads the `FileSyntax` of `ast-graph/` from the tree the blocks were read from. `readCodeGroup(files)` in `build-group.ts` returns the stored group and `readSyntaxByPath`, which reads the syntax of every file of the group the first time it is called. The syntax is not part of the stored form: it holds no reference, and it is what the diagrams read the inside of a node from. `buildStoredCodeGroupGraph` is the stored group alone, and `readCodeGroups` in `read-groups.ts` reads every group of a change with its syntax.
- **A symbol is stored by where it is held.** A symbol has no id, so `handedFrom` of a block and `externalSymbols` of a file hold a `StoredSymbolPlace`: the id of the block that holds the symbol and its index in that block's `outerSymbols`.
- **A value handed under a name goes to the argument of that name.** `findArgument` in `link-references.ts` hands a value written under a key to the key of the first argument, to a member read from it, or to the whole argument of that name, as a Python keyword argument is.
- **`readCodeGroupGraphs(change)` is the only part that reads.** `read-groups.ts` traces and clusters the import graph, splits each cluster with `splitIntoGroups`, reads the sources with one `blobs` call per commit and the changes with `diffsOf`. A changed file in no cluster, such as a migration, is a group of its own. A deleted file has no ranges.
- **A test and a story are read by no language.** Which files are tests comes from the test runners the repository installs and their configuration, as the locations of `locations/` read them, never from fixed globs. `readCodeGroups` takes them out of every cluster with `splitIntoGroups(cluster, isTest)` in `group-files.ts`, which splits what only they joined and drops the files that no longer lead to a change, and a changed test is a loose group of its own whose source says `isUnread`, so `outlineFile` gives it one `file` block and `grammarOfSource` no grammar.
- **Where a repository keeps its files is read from its tools' configuration.** `readRepository` in `read-groups.ts` lists the files at the head commit, and reads the manifests and every configuration file `listConfigPaths` names in one `blobs` call. `readRepositoryLocations` in `locations/index.ts` is a calculation from the manifests, those texts and `LIBRARIES` to rules: each library's `locations`, in the folder of every manifest that installs it and every manifest below one, a key's default when it is silent, the default of a folder leaving out the folders below that have a configuration of their own. `config-values.ts` reads a value by format: `text-config.ts` for JSON, TOML, INI, `.env` and YAML as data, `javascript-config.ts` and `python-config.ts` for code, parsed, where only a value written out counts and a key `name(argument)` is the argument of a call written anywhere. `path-values.ts` evaluates a path built from fixed parts (`path.join`, `path.resolve`, a file URL of `import.meta.url`), and `python-config.ts` reads a setting written on an object by key or in a class at the top of the file. `placedClassificationsOf` gives the classifications the rules place a file in, and each file source carries them as `placedClassifications`.
- **Every block is classified in one pass, after the chains.** `classifyGroup` in `classifications.ts` reads four signals of each block (its type, or its `deletedType`; its `catalogue`, through the category of its library; its `card`; its file path, through `TOOL_NAMED_LOCATIONS` and the file's `placedClassifications`) and the library uses each reading carries: every pattern match whose `classifies`, or the category of its library, gives a classification, placed on the innermost block that holds it. It hands each block's own classifications up to every block around it, never `logic`, and builds `diffClassifications` from the changed blocks only, falling back to the block's primary classification when they earn nothing. `withClassifications` puts both lists on each block of `build-group.ts`.
- **`DiffKind` is read from classifications.** `diff-contains.ts` maps each classification to one kind (`diffKindOf`), and `readKindsOf` maps the own classifications of each counted block, which `build-group.ts` hands it as `ownClassificationsOf`, adding `ui` for a block inside a function that holds a `render-root`. A type declaration's `data-model` gives `type`, which traces no chain; any other `data-model` gives `logic`.
- **The range of a change has columns.** `diffsOf(patch)` in `patch-ranges.ts` gives each change as a diff, with its range and its type: `added` for lines that were only added, `deleted` for lines that were only removed, `modified` for any other run. It pairs a run of removed lines with the same number of added lines and gives what each pair does not share. A line that is only added is its text without the blanks around it, and a blank one gives no range. Lines that were only removed are a position with no width on the line that took their place. Lines and columns start at one, and the end of a range is the column after its last character.
- **A language reads a file in two steps.** `languages/index.ts` picks the language by extension. `outlineFile` reads what a file declares and exports, and its `read(findExport)` makes the blocks and the uses, once `createExportTable` in `export-table.ts` can answer what a name of another file leads to: a callback passed by name counts only when the name leads to a function. A file no language here reads, or one that holds no block, is one `file` block that spans it.
- **TypeScript and JSX share one language.** `languages/typescript/blocks.ts` walks the tree with a cursor and makes the blocks, `calls.ts` says what a call, a `new` or a member read is (an effect, a listener, a global of the platform), `markup.ts` says what is markup, `arguments.ts` makes the `root-argument-value` blocks, `uses.ts` says how each name is used, `written-at.ts` says where a value is written (its attribute or its argument, and the keys of the object it is in) and under which keys a function of an object is, and `outline.ts` resolves every name once with the readers of `ast-graph/languages/typescript/`. `readScript` reads the blocks and the uses of one script, at the root of a file or, when it is handed the id of a component, as the body of that component. `decorators.ts` moves a block written in a decorator into the class, the method or the property the decorator is on (`withDecoratorsInside`, after the walk: the declaration's range starts at its first decorator, the block has the same parent and lies in that range). `class-members.ts` counts a parameter of the constructor marked `private`, `protected`, `public` or `readonly` as a member, so `uses.ts` reads `this.users` as a use of that parameter.
- **Python is read by its statements.** `languages/python/outline.ts` resolves every name with the readers of `ast-graph/languages/python/`, and `blocks.ts` walks the tree with a cursor: an `import`, a `function` from its first decorator, a `method` named after its class, a `class`, a `root-variable`, a `root-statement` around every other statement at the root, a `condition`, a `switch` with its `switch-case` blocks, a `loop`, a `try-catch`, a `throw`, an `external-value` below the root, and a `root-argument-value` per argument of a root function or of a method of a root class, without `self` and `cls`. A `with`, a name bound in the body of a class and a plain local are no blocks. A class of `TypedDict` or `Protocol` is a `type-declaration` with no block inside it. A function carries what the catalogue says of its decorator, and a call a pattern names is a block of the type the pattern makes. Any other call handed a callback, a `lambda`, a name that leads to a function (`findExport` says so of an imported name) or a keyword that starts with `on_`, is an `effect` with an `effect-callback` of each callback, as in TypeScript, or a `code-event` for a listening method; `map`, `filter`, `sorted`, `min`, `max`, `reduce` and the methods `map`, `filter`, `reduce` and `sort` are no effect. `uses.ts` says a name is called, read through a member, handed over by position or by keyword, or named in an annotation, and reads a member of `self` or `cls` that names a method of the class around it as a use of that method, which is declared at its name. A member that is called and names no method of that class is a use of each class it names as a base, with that member, and `followMembers` finds the method. A member that is only read is no use of a base. A file exports every name its root binds and every name it imports.
- **A Vue file is one component.** `languages/vue/index.ts` makes one `component` block that spans the `<script setup>` block and the template, named after the file, and it is the default export. The file is parsed once by `parseVue` of `ast-graph/languages/vue/`, and its trees serve the blocks and the syntax. The setup script is read by `readScript` as the body of that component, from the tree of the file with everything but the script blanked, so every position is a position of the file. An `import`, an `interface` and a `type` at the top level of the script are blocks at the root of the file, not inside the component (`isModuleWide` in `languages/typescript/blocks.ts`), so a change of an import is placed in the import. `template-blocks.ts` makes the `render-root`, a `render` per element, a `render-condition` for `v-if`, `v-else-if`, `v-else` and `v-show`, a `render-loop` for `v-for` and a `render-event` per listener. `template-uses.ts` reads the tree of the expressions of the template, each written where it stands, and resolves its names against what the setup script declares and imports and against the props, without the names an element declares itself. `component-arguments.ts` makes a `root-argument-value` per prop of `defineProps` and per event of `defineEmits`, named as its listener (`onSave`), reads `props.title` as a use of the prop and `emit("save")` and `$emit("save")` as a call of the event. An emit that is the whole value of a listener on a component of the repository is the event as a `value`, handed to the event listened for (`findHandedPlace` of `template-uses.ts`). The whole value of a bound attribute or of a listener on a component is handed to the prop or the event of that name. A `<script>` block without `setup` is read as a TypeScript file at the root. In a file with no `<script setup>`, `options.ts` lists the members of `methods` and of `computed` and the keys of what `data` returns, in the object that script exports as its default or hands to `defineComponent`, and the template resolves its names against them: the block of a member is declared at its key. It also lists the `props` and the `emits` of that object, each a `root-argument-value` of the component, reads `this.$emit("save")` as a call of the event, and reads a member taken from `this` in a function of that object as a use of the member, the key or the prop of that name (`listReceiverUses`). A `this` under a second function written with `function` is not read.
- **A library has the catalogue, or a file of its own.** A library that is only identified is in the catalogue. A library that needs handling of its own is a `Library` (`libraries/types.ts`: a catalogue library with an optional `readCards`, an optional `readExportCards`, and an optional `readUses`, which gives library uses a pattern cannot say, as the Express handler of four arguments that handles errors; `listOwnUses` in `libraries/cards.ts` runs it beside `withCards`) in `languages/<language>/libraries/`, listed in `TYPESCRIPT_LIBRARIES` or `PYTHON_LIBRARIES` of that folder's `index.ts`. `LIBRARIES` in `libraries/index.ts` is the catalogue's libraries and every language's, and every reader of this folder reads it.
- **A block says which card it belongs to.** `card`, a `BlockCard`, holds the library that wrote it, the kind of card, the part the block is, the heading it is drawn under, the key its card is grouped by and the block it is drawn in when that is not its parent. It is stored and linked as `catalogue` is, and `link-group.ts` gives each linked block `cardOwner`, the block `card.ownerId` names.
- **A library file writes the cards of its file.** `withCards` in `libraries/cards.ts` runs after the blocks of a file are read (`readScript` of TypeScript, so Vue too, and `outlinePython`): it hands each library with a `readCards` the matches of that library, the blocks of the file and `nodeAt`, which finds the syntax node of a range, and puts each `CardSeed` on its block, with the name the seed gives when it has one. `libraries/read-blocks.ts` finds blocks by range, the block of a call, the function written at a slot, and a block's children and root. `libraries/route-cards.ts` is the reading every route library shares: a call registration is the `holder`, its route slot the `handler` and its middleware slots `middleware`, a decorated function the `handler` itself and the middleware slots of its decorator `middleware` owned by it, each under the heading of its method (several methods under one heading, `GET · POST`; `ANY` for none, every method or a method with no heading) and grouped by the path below its prefix; a match that `isMounting` is a `mount` with its prefix as `groupKey`, and its middleware slots are `middleware` with no heading; middleware no registration or mount holds, a hook or a decorated function such as `@app.before_request`, is `middleware` with no `groupKey`. A slot with no block of its own falls to the property or callback that holds it (`preHandler: [auth]`), and a slot written as a call that hands a function in place, `Depends(verify_key)`, falls to that in-place slot. A library hands it how to name a handler written in place. `readExportRouteCards` is the reading of a route library whose routes are files: each block a file pattern of it names with `runs: "route"` and a path is a `handler` under the heading of its methods, grouped by that path. Flask marks `before_app_request` and `after_app_request` `isAppWide`. `withExportCards` in the same file runs after the file patterns (`languages/index.ts`): it hands each library with a `readExportCards` an `ExportCardReading`: the `BlockNaming`s of that library (the block, the names it is exported under and what a file pattern said of it), the exports of the file and `nodeAt` (`FileReading.nodeAt`, set by the TypeScript and Python outlines, `null` for Vue), and puts each seed on a block with no card. NestJS (`nestjs.ts`, library name `Nest`) has a `readCards` of its own: a class under `@Controller` is a `controller`; a method under a route decorator is a `handler` at the path of its block's `catalogue` (the controller's prefix already before it), with the `versions` of `@Version` or of the controller's `version` (a list gives each, `VERSION_NEUTRAL` none); the slots of `@UseGuards`, `@UseInterceptors`, `@UsePipes` and `@UseFilters` are `middleware` owned by that handler, or of the whole controller on a class; `useGlobal*` and `app.use`, and `useClass` / `useExisting` of a provider of `APP_GUARD`, `APP_INTERCEPTOR`, `APP_PIPE` or `APP_FILTER` (every path, `routePatterns`), are `isAppWide` middleware; what `consumer.apply` hands is `middleware` with the `routePatterns` of the paths `forRoutes` writes and the `excludedRoutePatterns` of `exclude` (`readRoutePatterns` in `nestjs-paths.ts` turns a Nest path into a regular expression, and reads the `method` of `{ path, method }`, `null` for none or `RequestMethod.ALL`); `setGlobalPrefix` is an `isAppWide` `mount` with its `excludedRoutePatterns`, `enableVersioning` a `versioning` part with its prefix (`v`) as `groupKey` for the URI type and `null` for any other, and its `defaultVersion` as `versions`; a class with a method under `@Query`, `@Mutation`, `@Subscription` or `@ResolveField` of `@nestjs/graphql` is a `router` `holder`, each such method a `procedure` under QUERY, MUTATION, SUBSCRIPTION or FIELD; the `module` of each `RouterModule.register` entry is a `mount` at the path of its entry and those above it, and `controllers` of `@Module` a `mount` with no prefix. A slot with no block of its own (`new CacheInterceptor()`) falls to the decorator's call around it. Next.js (`nextjs.ts`) seeds route handlers, the default export of a page as a `page` with its path, and `middleware` / `proxy` as app-wide middleware whose `routePatterns` (no method) `nextjs-matcher.ts` reads from `config.matcher` (Next.js path patterns turned into regular expressions; every path when there is none or one cannot be read). `libraries/store-cards.ts` holds the headings of the store parts and the seed of a part. A library file imports only its language, `libraries/` and `reading.ts`.
- **The card links run after the references.** `linkCards` in `card-links.ts` runs on the stored blocks after `followMembers`, with no language, and repeats until nothing changes: a function a route slot names is that slot's handler, owned by the registration, under the heading of its own `catalogue.method` when the registration's is ANY (`headingOfHandler`, Django's `@require_POST`); a function handed to a call of a store's holder is a selector of it; a function whose first argument reads the key of a store (its `groupKey`, the name of a Redux slice), or a selector whose function reads it, is a selector of that store; a selector built on an owned selector is owned by the same store; a thunk an extra reducer names is owned by its slice; a part written in a call that names a holder is owned by that holder; a value whose every key names a holder of a router, a store or an API is a holder with no part; a method of a view class a route slot names through `as_view` is that slot's handler, under the heading of its own method when its name is one of HTTP, and a view class with no such method is itself the handler, under the slot's heading. A link fills a block with no card, or the `ownerId` of a card of the same part.
- **A call on a tRPC client steps to its procedure.** `listCalledProcedureIds` in `procedure-calls.ts` runs inside `traceChains`, on the stored blocks with their cards. A block whose `catalogue.specifier` is `@trpc/client` or `@trpc/react-query` and that calls a member path of a value with more than one name is a client call: the path without its last name, the method, names the procedure. The routers come from what the client names as a `type`: a router holder, or a `type-declaration` whose value is one (`typeof appRouter`), else every router no property of another router names (`listTopRouters`). Each key is matched against the nearest properties of the router (`listNearest`, which does not descend into another property), going on into a router the property names, and the last key gives the procedures inside its property. `listSteps` adds those ids to the steps of the call, so a client call leads to a change in its procedure and the walk of a trace crosses into the router card.
- **The mounts run after the card links.** `mountRoutes` in `route-mounts.ts` reads every `mount`: the router it is on and what it hands over, from the symbols, its named values and a function written in it. A route takes the prefix of every mount above its router (the class of a decorated method, else `routerIdOf`, the target of the symbol that calls a member of it, or of the registration it is chained on) before its `groupKey` and `catalogue.path`, the first prefix found when the router is mounted in several places; a mount written in a decorator of a class is on that class. The `isAppWide` parts of a library then go before each of its routes (`appPathsByLibraryOf`): a `versioning` part the versions of the route or its own, in one segment (`v1|v2`), or after the heading of the handler and its owned middleware (`GET v2`) when its `groupKey` is `null`, and nothing for empty `versions`; then a `mount` its prefix unless an `excludedRoutePatterns` entry matches the path before them and has no method or the handler's `catalogue.method`; a plugin's routes have their prefix from matching already, so a mount adds a prefix only to a router it names, and a parameter of a mounted plugin counts as the plugin only for middleware and a mount slot that names a router loses its card. Middleware no registration owns gets `routePaths`, the paths of the routes of the first block above it that names a router (`coverageOf`): first, at any height, a mount that hands over routers, or the router the mount is on below its prefix, a block that is a router, or one that names routers (`forRoutes(UsersController)`); then a call on a router. A registration or a mount with no router of its own is on the `root-variable` that holds it (`valueAroundOf`, Django's `urlpatterns`), and a mount hands over every `root-variable` of the file of a module it names, by `card.mountedModule` or an unopened import of a whole module of the repository (`listModulesImportedWhole`, relative imports resolved against the mount's file), matched by the end of the file path (`isFileOfModule`). An `isAppWide` card climbs to the top router of the mounts, never past a `mount` whose card says `isAppMount` (`app.mount` of FastAPI), and reaches every route of its library when nothing above names a router. Only an `isAppWide` card crosses an `isAppMount` mount on the way down (`mountsCrossedBy`), so the dependencies of an app stop at an app it mounts. Middleware with `routePatterns` gets instead every path of a registration or a `page` part in the group that a pattern matches (a pattern with a `method` only registrations of that method or of `*`), a dynamic segment `[team]` read as `team`, tried also below the app's prefix and below its version, with the routes of the routers a block above it names. A path an `excludedRoutePatterns` entry matches is left out; one that names a method only when every registration of the path has it.
- **A symbol keeps the name it imports from a declaration of several.** `symbolOf` in `link-references.ts` sets `binding` on an `external-block` symbol whose block declares several names and is named after another, so what is called is named after the name imported.
- **A value at the root says whether it is plain.** `isPlainValue` in `languages/typescript/plain-values.ts` and `languages/python/plain-values.ts` sets `isPlain` on a `root-variable` whose value holds no call but `new`, no function, no markup and, in Python, no comprehension or `await`, at any depth. `new` is left to the Trace Diagram, which knows whether the class has a method.
- **A decorated Python function takes the method of any of its decorators.** `catalogueOfFunction` in `languages/python/blocks.ts` keeps the catalogue of the first decorator a pattern names, and its `method` from the first decorator that says one (`methodOfDecorators`), so `@login_required` above `@require_POST` keeps POST.
- **A Python value of `Annotated` is an annotated alias, and a call in an annotation runs.** `languages/python/annotated.ts` knows both shapes of `Annotated[…]`: a `subscript` (`typing.Annotated[…]`, and any value) and the `generic_type` an annotation parses `Annotated[…]` to. `readAssignment` sets `isAnnotatedAlias` on a `root-variable` whose value is one, carried as `isPlain` is. `readPythonUses` reads a name as a `type` only when an annotation is closer than any call (`isTypeUse`), so `Depends(current_user)` in an annotation is a call handed `current_user`. A call of the metadata with no argument is handed the annotated type: `callFilledByAnnotatedType` and `annotatedTypeFilling` make `Pagination` in `Annotated[Pagination, Depends()]` the first value passed to `Depends()`, in `passedTo` of the catalogue's `python-reader.ts` and in `passedValuesOf`, `isPassed`, `callPassedTo` and `slotNameOf` of `blocks.ts`, so its slot makes an `effect-callback` of it. In `chains.ts`, a `type` use steps to an annotated alias, a function steps into a parameter typed by one (`isTypedByAnnotatedAlias`), and a callback that runs `in-place` is a step of whatever block holds it (`isRunInPlace`).
- **A function says when the function around it returns it.** `isReturnedFunction` in `languages/typescript/returned-functions.ts` and `languages/python/returned-functions.ts` sets `isReturned` on a function written in a `return`, as the body of an arrow function, or declared in a body whose `return` names it. A TypeScript constructor parameter marked `private`, `protected`, `public` or `readonly` gets `isParameterProperty` (`readWhole` in `arguments.ts`, through `isParameterProperty` of `class-members.ts`), carried as `isPlain` is. `isReturned` of a read call stays a hint for the chains; `link-references.ts` stores it only on a `function`, a `hook`, a `component` and a `method` (`RETURNED_TYPES`).
- **The id of a block is derived.** `blockIdOf` gives the file path, the type and the start, such as `src/page.tsx#function@12:1`. Two blocks of one type that start at the same place, as the calls of `bus.on(…).on(…)` do, are told apart by the end of the inner one.
- **References are filled in after every block exists.** `linkReferences` in `link-references.ts` holds each use in the innermost block around it, leaves out a name declared inside that block, and turns an import into a block through the export table. It fills `usedBy`, `handedFrom`, the `exports` of each file and `exportedBy`.
- **A change belongs to the innermost block around it.** `placeDiffs` in `diff-blocks.ts` nests the ranges of the blocks of a file and descends to the innermost one that holds a change. A range that crosses the edge of a block is cut at the edge, and each part belongs to the innermost block around it. A change outside every block belongs to the root block that follows it, or to the last one.
- **A statement that is a call is a `call`.** `readCallStatement` in `languages/typescript/blocks.ts` and in `languages/python/blocks.ts` makes a `call` of an expression statement below the root whose expression is a call, awaited or not, that no other reader makes a block of, named after what is called when that is a name or a member of one. The uses written in it are held by it, as the innermost block around them, so a chain steps from the holder into the call and from there to what it calls. `chains.ts` reads a `call` as part of the handler it is in, as it does a variable.
- **A class that extends another and renders markup is a component.** `isClassComponent` in `languages/typescript/markup.ts` reads a class with a heritage clause whose `render` method returns markup, and `readClass` and `readDeclarator` in `blocks.ts` make it a `component` block, whose methods are blocks inside it.
- **A write to a member of a parameter is a `property`.** `parameterMemberWrittenIn` in `languages/typescript/parameter-writes.ts` reads an assignment, an operation and an update whose target is a member of a parameter of the innermost function around it, and `readWrittenParameterMember` in `blocks.ts` makes a `property` named after the member, `state.items`, one per write.
- **A name declared below the root is a `variable`, and a key that holds a value a `property`.** In `languages/typescript/blocks.ts` `readDeclarator` makes a `variable` of a local declaration no other type claims, `readBound` of an argument of a function below the root, of a name a `for … of` binds and of a caught error, and `readOption` and `readField` a `property` of a key and of a field that is no function. `languages/python/blocks.ts` does the same for a local assignment, an argument of a nested function or a lambda, the target of a `for`, an attribute of a class, the first `self.name = …` of a class, and a key of a dictionary written as text. `languages/python/members.ts` lists the attributes of a class and reads the key path of a dictionary, and `uses.ts` reads `self.name` and `CONFIG["key"]` as members, and gives a second use, a read of the key, for `CONFIG.get("key")` of a name the group can open. In TypeScript `class-members.ts` lists the members of a class, the ones first set through `this` among them, for `readAssignedMember` in `blocks.ts` and for the receiver uses. An argument block is marked `isParameter`, so it holds no block that follows it. `findWrittenMember` and `findMethod` in `value-origins.ts` lead a member to a property as they do to a function.
- **Code that was taken out is a `deleted` block when it stands alone.** `diffsOf` keeps the removed lines of a change that only removed lines. `listDeletedCode` in `deleted-blocks.ts` reads them with the grammar of the file (`grammarOfFile`), as members of a class when they were inside one, and makes a block with no width where they were: at the root for anything that parses, inside a block for a declaration only. `listRemovedDecorations` gives removed decorators to the block that starts on that line: lines are decorators when they parse above a class, a member or a function written after them and add no declaration of their own. `readCodeGroup` adds the blocks to the file after the other changes are placed, so no other change lands on one.
- **For the chains, a variable, a property and an argument change with their holder.** `sourceOf` in `chains.ts` climbs from one of the `OWNED_TYPES` to the block around it, `isHandlingBlock` reads a variable and a property as part of the handler they are in, and `runMemberOf` does not step to a property: a read of a key still leads to the value it is read from. A `deleted` block is among the `UNTRACED_TYPES`.
- **A block that uses a changed block is affected.** `traceAffectedDiffs` in `affected-diffs.ts` visits the files from the root files down the imports (`listFilesFromRoots`), and again from each file a loop of imports kept out of reach. It adds a diff of the type `affected` to `diffs` at each use of a block that has a change written in it or inside it. The used block is the member a symbol leads to when it has one, never a `root-argument-value`, and never the using block, a block around it or a block written inside it. A symbol whose member leads to no block is passed over when a wider symbol of the same name leads to one, and of two uses of one block the wider range is kept. It leaves `lineOfCodeDiffs` alone, so an affected block is not a diff block.
- **A member reached through `this` or `super` is a use.** `readReceiverUse` in `languages/typescript/uses.ts` gives a use of the method or the function field of the class a `this.name` is written in, and of the class it extends when the class has no such member or the receiver is `super`, for a call and for a read alike. A `this` inside a function with a receiver of its own gives none. Python does the same through `self`.
- **`diffContains` is read from the diff blocks.** `readDiffContains` in `diff-contains.ts` gives the kind of each diff block's type, and `ui` for a `component` block and for a block inside one, or inside any other function that has a `render-root`. A block of a type with no kind of its own, outside a component, is `logic`.
- **A chain steps where code runs.** `traceChains` in `chains.ts` lists, for every block, the blocks it runs next: the blocks nested in it that run with it, the block behind each symbol it calls or renders, the function written in place in an event, a callback or a loop of markup, the callbacks of an effect that keeps no result, and the methods of a class. A handler passed by name to an element or a call outside the repository is run by its event or callback. An argument block runs what each place hands it when the argument is called: `listCalledArgumentIds` names the arguments a symbol calls or renders, those an event or a callback is handed as its handler, and those a called argument was handed in turn. An argument that is only read, also as the first value of a `state`, takes no step. A declaration that keeps the result of an effect is two steps apart: the block that holds the declaration steps to the call, and a use of the declaration steps to it and from there to the callbacks of the call. A declaration at the root of a file has no holder, so a use of it steps to the call too. `nextBlocks` is those steps that lead to a change, `diffSources` the changed blocks a block leads to, and a top is a block on a chain that nothing runs. A use of a value, a `root-variable`, a `state` or an `external-value`, steps to it whatever the use, and a function steps into an effect it returns. An element outside a `render-root` and outside a page slot is a `value`, not a `render`. A function passed by name to a method of a list or of a promise, `items.map(priceOf)`, is a `call`. An argument block starts no chain, and a changed argument is traced as a change of its function. A type, an import and a `file` block are never traced and take no step.
- **A use of a block declared inside the holder is a symbol.** `linkReferences` keeps a use of an argument, a function, an `external-value` or a `variable` declared inside it, since a chain steps through them and a change to one affects its readers. It leaves out a name the block declares that is no block.
- **A member a callback takes from a value is a use of that value.** In `useCartStore((state) => state.addItem)`, `uses.ts` reads `state.addItem` as a use of what was called, `useCartStore`, with the member `addItem`, when the callee is an import or a declaration at the root of the file. A function written in place in an `effect-callback` runs what it names, so a call of the kept result reaches the action. This is assumed: nothing proves the argument of the callback is the value.
- **A member is followed to the origin of its value, by its whole path.** `followMembers` in `value-origins.ts` runs after `linkReferences`, with what `linkReferences` kept of each use: where it is written (`writtenAtBySymbol`) and the keys of each function of an object (`memberPathById`). For a symbol with a member that names a value, `followPath` looks in that value for a function written under the keys the path starts with, the longest that fits, or else for a function of that name declared inside the value, as an action of a store written as a setup function is, then follows every name the value holds: a name under a key the path starts with, a name with no key, what an object spreads, what a function or a hook it calls returns, what a variable it calls holds, as `useCartStore` of `const cart = useCartStore()` does, the methods of a class it makes, and what a context provides. A method is looked up in the class and then in the classes it names as a base, nearest first (`findMethod`): a base is a use written as one, `isBase` of `WrittenAt`, which `extends` in TypeScript and the list after the name of a Python class set. A member of a symbol that names a class is found the same way, and so is a member of a parameter, a property or a value that nothing else leads to when the block names a class of the repository as its type (`findTypedMethod`): `this.users.findAll()` with `constructor(private readonly users: UsersService)` reaches `UsersService.findAll`. A use of a name taken apart in a declaration carries every key it was taken through, `const { orders: { remove } } = api`. A context is followed only where a call the catalogue names with `reads` is handed it at `reads.keyAt`, and what it provides is read from the place `provides.valueAt` names: the `value` attribute of the element of a factory with `provides`, as `createContext` of React has, or the argument of a call with `provides`, as `provide` of Vue. A context is also followed from an element the catalogue names as a reader: `uses.ts` reads a member the function written inside `<ThemeContext.Consumer>` takes from its first argument as a use of the context with the path `Consumer.<member>`, and `followThroughReader` follows the rest of the path through what the context provides. `linkReferences` itself sets `member.block` only for a member of an argument that is not taken apart.
- **`fetch` is a `data-fetch` when the call says it reads.** `typeOfCall` in `languages/typescript/calls.ts` makes a call to the global `fetch` a `data-fetch` when it has no options, or options written in place that name no method or the text `GET`, in any case. Options that are a name, that spread another object or whose method is a name make it a `request`. `typeOfConstruction` makes `new EventSource(…)` a `data-fetch`. Both count as `data` in `diffContains`.
- **A call that provides a value is no effect.** `typeOfHandedCall` in `languages/typescript/calls.ts` makes no block of a call a pattern names with `provides`, which `isProviding` of `named-by.ts` says, so a function handed to `provide(key, { toggleTheme })` is a `value` use, not an `effect-callback`.
- **An `effect` runs with the block that holds it, a `component-effect` that keeps no result starts a chain.** A function with no name written in place runs with its holder too, which is assumed. A call handed a callback inside the attribute of an event is an `effect`, not a `component-effect`: `blocks.ts` reads it as elsewhere once it is inside a `render-event`.
- **`chainContains` is read from the blocks on the chains**, by the same kinds as `diffContains`. No chain is traced when `diffContains` holds only `type` and `file`.
- **The catalogue names state.** `languages/typescript/made-by.ts` matches the call a declaration keeps against the call patterns of `LIBRARIES` that have `makes: "state"` or `"derived"`, through the import of the name or of the whole library, and the declaration becomes a `state` or a `derived` block with its `catalogue`. A match of `named-by.ts` that makes state does the same through the origin of what is called, so a declaration that keeps what a zustand store hands back, `const status = useOrderFilterStore(selectStatus)`, is a `state` block.
- **The catalogue names the other blocks through `named-by.ts`.** A file is matched once with `matchSyntax`, and `createFileNaming` answers by the range of a node. A call a pattern matched is a block of the type the pattern makes, or a `route`, a `resolver` or a `middleware` when it has a slot that runs as one and does not make a value with a factory, and keeps its syntax type otherwise. A decorator's own `runs` comes before the runs of its slots, and of the decorators of a method the one that runs something other than middleware wins (`mostTellingOf` in `blocks.ts`). Its `catalogue` holds the specifier, the name, the path, the method and the event. A callback the pattern names is a block even when its name leads to no function, is a `code-event` when the slot runs on an event, and has `catalogue.runs`. A property a pattern names as a slot is a block at any depth of the options, as `element`, `Component`, `loader` and `lazy` of a route of `createBrowserRouter` are, each with the path of its route, and an element written in a slot that runs as a page is a `render`. An element, a class and a method keep their type and get the `catalogue`: a decorated method has the route of its decorator with the prefix of the first decorator of its class that has one before its path, which always starts with `/`, and a method of a class that extends an export has what the class pattern says of that member.
- **A value is followed into the file that makes it.** `buildStoredCodeGroupGraph` hands every file a `findBinding`, which finds the declaration behind an export through the export table and asks the file that holds it.
- **A file pattern names the block behind an export.** `readStoredCodeGroupGraphs` reads every manifest of the repository at the head commit (`manifests.ts`: `package.json`, `pyproject.toml` and `requirements*.txt`), and each file gets the nearest one above it: the packages it lists and the path of the file from its folder. `listExportNamings` in `languages/file-catalogue.ts` matches that path against the file patterns of the libraries the manifest lists, `listBlockNamings` gives the block behind each export its `BlockNaming`, and `withExportNamings` leaves it on the block as its `catalogue`, with the path of a page or a route read from the folders of the file below the first folder of the glob by `routePathOf`. The first pattern that names an export holds; a block exported under several names of that pattern has all their methods, joined by `METHOD_SEPARATOR`. A manifest lists a library under a specifier of the library or under a registry name the library list in `data/libraries.ts` gives it, so `django-allauth` is the library imported as `allauth`. A file with no manifest matches no file pattern.
- **A directive names the functions of its file.** `languages/typescript/directives.ts` leaves what a directive pattern says, such as `"use server"`, on every exported function of a file that starts with it, or on the one function that starts with it.
- **A route runs its handler.** In `chains.ts` the callbacks of a block the catalogue names are steps of that block, as the callbacks of an effect are.
- **A component is a block type.** `typeOfCallable` in `languages/typescript/blocks.ts` makes a function a `component` when it returns markup and is not written in markup, unless its name makes it a `hook`, and `readDeclarator` makes a variable that holds markup a `component` too, with the markup as its `render-root` and `holdsMarkup` on what was read. Both hold at any depth of a file. `traceChains` in `chains.ts` is handed the ids of the blocks that hold markup: such a block runs with the block that declares it and is reached by any use of it, as a value is, where a component that is a function is reached only where it is called or rendered.
- **A group is cut into segments here.** `cutSegments` in `segments.ts` reads which file uses which from the symbols, and which uses only hand a function, a hook, a component or a class over without running it (`handsOver` of `listFileUses`): naming it as a value, or writing its element where no component, hook, function or method holds it, as `element: <OrdersPage />` in a route table (`isRenderedOutsideRunningCode`). `layoutPaths` of `listFileUses` are the files handed over through a layout: a route element of the catalogue (`runs: "page"`) beside a property that holds other route elements whose paths are within its own (`isLayoutSlot`). A changed file is shared when two files use it, when it is the layout of a route, when it hands over two or more lines of change it does not run (`listLinesHandedOver`), or when two or more lines lead to it. `listLines` starts a line at each other changed file no file on a line leads to, through any files but what a shared file hands over, and gives each remaining file the line that leads to it. `listBlocksUsing` gives the blocks that hold or use a changed block of some files, directly or through other blocks, and `listReachedFilePaths` the files among them the diff did not touch.
- **A file says what its own diff holds.** `diffContains` of an `ASTGraph` is read from the blocks of that file alone.
- **A file can be asked which call hands one of its exports in place.** `readCodeGroup` gives every `read` a `FindHandedExport` beside `findBinding`: it asks the other files' `handingsOf`, which a TypeScript file answers from its imports of that export and its `require` calls of that file. The outline exports what `module.exports` holds as the whole module (`*`), a function written there is declared at `module.exports`, a top-level function declaration is file-wide (so `export { priceOf }` exports it), and a `require("./x")` handed to a call is a `value` use of that whole module.

## Layout

```
types.ts            the shapes in memory: a group, a file, a block, a symbol
stored-types.ts     the same shapes with every reference as an id or a file path
reading.ts          what a language hands back: blocks, uses and exports
build-group.ts      the files of a group → its stored form
link-group.ts, store-group.ts  the stored form → the group in memory, and back
read-groups.ts      a change → its groups, read through git-forge
group-files.ts      the files of a group, without what a predicate leaves out
classifications.ts  what every block is for and what a change to it does, and the classifications a path is named for
locations/          where the tools of a repository keep tests, migrations, models, configuration, translations and infrastructure
patch-ranges.ts     a patch → its changes, each with a type and a range with columns
export-table.ts     a file and a name → the declaration behind it, through re-exports
link-references.ts  the symbols of each block, and every reference between blocks
diff-blocks.ts, diff-contains.ts  the block around each change, and the kinds of change
affected-diffs.ts   the blocks that use a changed block
deleted-blocks.ts    the blocks of code a change took out
chains.ts           what each block runs next, the changed blocks it leads to, and the tops
procedure-calls.ts  the tRPC procedure each call on a tRPC client names
value-origins.ts    where a value comes from, and the function behind a member of it
segments.ts         the entry segments and the shared segment of a group, and the files a change reaches
source-range.ts     positions and ranges
manifests.ts        the manifests of a repository, and the one nearest above a file
languages/          the registry, typescript/ for TypeScript and JSX with named-by.ts for what the catalogue says of a block, python/, vue/, and file-catalogue.ts for what the path of a file says of its exports
```
