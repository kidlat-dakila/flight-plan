# packages/codegraph/src/trace-diagram

The Trace Diagram of a segment, drawn from the chains of its group. Read [Trace Diagram](../../../../docs/vocabulary/trace-diagram.md) before changing anything here. The rules of [packages/codegraph/AGENTS.md](../../AGENTS.md) hold here too.

## Rules

- **A trace is drawn from the group in memory.** `generateTraceDiagram({ group, importGraphGroup, scope })` in `index.ts` takes the `ASTCodeGroupGraph` that `linkCodeGroupGraph` made and returns one `TraceDiagram` for a segment, or `null` when no chain leads to a change in it or when its nodes would draw no edge (`traceNodeEdges` empty after the card edges): one card alone, or cards nothing joins, show no flow. A test that checks one card gives the change a line into it. The diagram holds the group, the import graph and every block as the same objects it was handed.
- **A node is a root block, or a block inside one that something triggers.** `walkChains` starts at the tops of `diffChains` that the scope keeps (see the rule on an entry segment below) and follows `nextBlocks`. `isNodeBlock` in `node-blocks.ts` says which blocks are nodes, as the table of [Nodes](../../../../docs/vocabulary/trace-diagram.md#nodes) does: a root block that is no `root-statement` and no folded value, an event, an effect, a callback but the one an effect hook is handed (`isMergedCallback`), a route, a resolver, a middleware, a call the catalogue types that is handed a callback that does not run in place (`isCatalogueCallHandedCallback`, `api.todo.create.useMutation({ onSuccess })`) and a memo (`isMemoBlock`) inside a `component` or a `root-statement` (`hasNodesInside`), but a call of a value a library made that is handed only callbacks that run in place and its callbacks (`isFoldedCall`, `isFoldedCallback` of `repository-calls.ts`), and, in any root block, a block whose `catalogue` says `isOwnNode`. Nothing inside such a block is a node (`isInsideOwnNode`), nor anything inside a memo (`isInsideMemo`). A card can say a block is a node (`isCardNodeBlock`) or that it is none though the rest says it is (`isCardNotNodeBlock`, read first). Every other root block is one node with all that is written in it. The call of a `state` or a `derived`, a callback that runs in place, a function written in place of an event or a callback and a function an event of the same root block is handed by name (`eventHandedTo`, read from `usedBy`) are no nodes. Such a handed function belongs to the node of its event: `nodeBlockOf` and `nodeBlockAround` climb from it to that event, not to its parent. They climb from a block with a `cardOwner` to that owner, and from a property declared in a constructor, or a constructor parameter with `isParameterProperty` (`declaresProperty`), to its class (`classOfDeclaredProperty`), in the same way (`blockAround`). `isStepBlock` says which other blocks are steps, for the band: a function or a method, and a block that is executed anywhere but on the way to the `return` of a component or a hook. `nodeBlockOf` gives the node block a block is in, or `null` for a block of a `root-statement` that no node holds, and `nodeBlockAround` the one around a node block. A block with no node block is in no node, and a step that leaves it or reaches it is no edge.
- **A value that is not exported, and plain code, are folded into the nodes that read them.** `isFoldedValue` in `node-blocks.ts` says which: a `root-variable` that is not exported and holds no block of the types that run (`RUNNING_TYPES`), or a root block that is plain (`isPlainRoot`): a `root-variable` whose `isPlain` is set and that makes no class of the repository with a method by `new` (`makesClassWithMethods`), a `root-variable` whose `isAnnotatedAlias` is set, or a `class` with no method that is no router (`isRouterClass` in `cards/class.ts`: a controller, or a class that holds a `mount` part, such as a NestJS module). Either is folded when a block in a node reads it (`usedBy`) and steps into it (`isSteppedInto`, from `nextBlocks`): a type that names it, or a call it is only handed to, folds nothing, so the value keeps its node. A `class` is folded only into a block that calls it as well (`isMadeBy`, `new Point()`), so a class a block only names keeps its node though the block steps into it: the pydantic model of `response_model=` (`filled-classes.ts` of `code-blocks/`) and a class handed to `Depends()` each keep a card with a line from the handler. It is no node, and `foldedValueOf` gives the folded value a block is in. `listFoldedValueHolds` in `index.ts` gives each node with a step into a folded value, directly or through another folded value, the shown blocks of that value, so `toTraceNode` holds them and `listListedBlocks` lists the value as a step. `stepsInto` carries a step into a folded value on to what it leads to. The Code Walkthrough reads a folded value as it reads a node, so its waypoints do not change. [Values that are not exported](../../../../docs/vocabulary/trace-diagram.md#values-that-are-not-exported) and [Plain code](../../../../docs/vocabulary/trace-diagram.md#plain-code) have the rules.
- **Every block on a chain and every changed block is in the nearest node around it.** `listShownBlocks` gathers them, but for a root block of a file outside the segment that holds a block leading only to the change of another line (`handsOverOtherLines`, read from `leadsOnlyToOtherLines`), such as a route table that names the pages of other segments, it keeps only the blocks the walk passes through, `listNodeBlocks` gives the node block of each and every node block around it up to the root, root blocks first, and `listNodes` makes one node per node block.
- **An edge is a step between two nodes, or a node inside another.** `listNodeSteps` in `node-blocks.ts` turns the steps of the walk into steps between nodes: a step that stays in a node or only goes further inside it is none, a step from an effect or a memo (`isHookCallBlock`) into a block of a node around it that it does not call (`isOnlyRead`), such as a value of its component it reads, is none, a step through a block of a node around is carried on to what it leads to, and so is a step from inside a step block through a value of its own node, so that the band can join the row of the step. `listHeldNodeEdges` adds one edge from the node around each inner node. `listEdges` keeps each pair once. The band reads `listNodeSteps` too, so the lines of the page and the edges of the diagram cannot disagree.
- **`added-cards.ts` builds what an author adds.** `readFileGraph` reads one file as a group of its own, `listCardBlocks` lists the root blocks a card can stand for, `buildBlockCard` and `buildLinesCard` make the node, and `listCardRows` gives the rows of any node: the stored `rows`, or the rows the page lists from its `codeBlocks`. Editing a diagram is the backend's `procedures/edit-trace/`.
- **What a row is depends on the card.** `toCandidate` in `listed-blocks.ts` lists no node drawn inside the node (`isNodeDrawnInside`); in a store holder, lists each block under the part around it as one row of the kind `part` (`storePartAround`) and no block that holds parts (`holdsStoreParts`); lists a `property` of a `class` node under `property`, also one declared in its constructor; lists a parameter of the node itself as an argument, as it does a parameter of an event or a callback; in a method of a class, lists nothing reached through `this.` or `self.` (`isOwnClassReach`), nor a `property` written in the method; and lists no middleware the node owns, nor a block whose every child is such middleware (`handsMiddlewareTo`), as the decorators of a NestJS handler.
- **A node holds its blocks in the order they are written.** `toTraceNode` puts the block of the node first, then the blocks a chain passes through and the blocks with a change inside it, down to the blocks that are nodes of their own. `diffCodeBlocks` are those with a change, and `triggerLabels` those after the first of the types `render-event`, `code-event` and `data-fetch`, each with a `null` label. `blockLabels` are the rows of the node an agent writes a label for, each with a `null` label (`listBlockLabels`): for a node whose block `isFunctionCardBlock` or `isHookCallBlock`, the calls, the returns and the raises that `listFunctionCardLabels` in `function-card.ts` gives, a call and a return with `at`; for a node whose block `isComponentCardBlock`, the calls, the memos, the effects and the render rows that `listComponentCardLabels` in `component-card.ts` gives; for any other node, the listed blocks `listListedBlocks` in `listed-blocks.ts` names, its arguments, state, hooks, effects and steps. `labelsOfSites` puts the entries in the order written and gives `at` only to a site that has one.
- **A function card lists what goes in and what comes out.** `isFunctionCardBlock` in `function-card.ts` says which node blocks are function cards: a `function`, `method`, `hook`, `render-event`, `code-event` or `effect-callback` whose `card` is no `holder`. `listFunctionCardRows(nodeBlock, insideBlocks)` gives its rows. Its calls are read from its own blocks (`listOwnBlocks`, with those of a function an event of it is handed, `listHandedFunctions`) and from the inside blocks of the node outside its block that are in no folded value (`isHeldOutside`), such as a function its handler calls; its exits from its own blocks. `parameters`: the parameters of the node block and of a handed function, but `self`, `cls` and `this`. `calls`: one `CallSite` per call symbol, in the order written, with the `callee` it is grouped under and the `called` block its line goes to (`calleeOfSymbol`): a function, a hook or a class of the repository, the class of a method called on what it makes (`outsideCalleeOf`), the function whose call made a declared value the call reaches, read from the declaration and the blocks right inside it (`declaredCalleeOf`, `originOf`), where a member of that value is followed only when it is called by its bare name or is itself a function, a method, a hook or a class of the repository, and a method of the repository called on a value with no known origin is grouped under its class, a store, a generated RTK Query hook, a thunk or a tRPC procedure (`repositoryCalleeOf`), a store or a function of the repository a hook of a library is handed (`libraryHookCalleeOf`), or a parameter of the node or of a function around it (`handedCalleeOf`). A symbol of a library or the language, any other member of a value of the repository, a call of its own class through `this` or `self` (`isOwnClassCall`), a parameter handed to a collection or a promise method (`isRunInPlace`), a call inside a `throw` (`isInThrow`), a call inside a trigger of the node, a `render-event`, a `code-event` or a `data-fetch` (`isTriggerInside`), whose trigger row holds its line, and a symbol written in a decorator of the block (`decoratorLinesOf`, `isWrittenInDecorator`) give none. `exits`: each `throw` block, and each `returnsAt` of its own blocks. `siteIdOf` names a call or a return `<block id>@<line>:<column>`, and a raise by its block id. [Function card](../../../../docs/vocabulary/trace-diagram/function-card.md) has the rules.
- **`hook-calls.ts` says which blocks are effect hooks and memos.** `isEffectHookBlock`: a `component-effect` handed a callback the catalogue says runs as an `effect`, `useEffect`, `watch`, `watchEffect`, `onMounted`. `memoCallOf`: the `component-effect` of `useMemo`, `useCallback` or `computed` that a `derived`, an `external-value` or a `variable` holds, and `isMemoBlock` a block that holds one. `hookCallOf` gives the call of either, and `isHookCallBlock` says a node block is one. `isMergedCallback` says a callback is handed to an effect hook, so it is no node and is read as part of its effect, `isInsideMemo` that a block is inside a memo, and `isSourceCallback` that a callback of an effect hook is no effect of it, the watched source of Vue `watch`. A `component-effect` that is neither, `useMutation({ … })`, keeps its callbacks as nodes.
- **`repository-calls.ts` says which calls of a value a library made are rows.** `repositoryCalleeOf`: a call through a member that steps to a `procedure` (`procedureReachedFrom`) reaches that procedure, the callee of a tRPC client hook or a server caller; a call by name of a store, a block with a `store` or an `api` card or a `state` at the root of a file (`isStoreValue`), reaches the store, and a call by name of a value that reads the holder of such a card, a hook RTK Query generates, reaches that holder, with the endpoint its name gives (`endpointOf`, `endpointNameOf`, `useGetTodosQuery` to `getTodos`) as the block its line goes to. A call through a member of a store reaches the store, with the part of its card that the last key of the member names, the block the member resolves to when it has that name or else the part of that name, as the block its line goes to (`partCalleeOf`, `storePartCalled`: an action, a reducer, a getter), so a method of the language or of a collection on its state, `state.memberIds.includes(id)`, reaches nothing. Every other call of such a value, a method the library gives the store object (`set`, `get`, `send`, `setState`) among them, reaches nothing. `libraryHookCalleeOf`: a call of a `use*` hook of a library that makes no effect and no memo (`isOwnHookCall`) reaches the store, or the function, hook or `derived` at the root of a file, it is handed as an argument or as an in-place callback that only names it (`valueHandedTo`), `useSelector(selectMembers)`. `isFoldedCall`: an `effect` or a `component-effect` that is no effect hook, whose callbacks all run in place, and that calls a store by name or a hook of a library handed a store, `useBagStore((state) => state.count)`; `isFoldedCallback` a callback of one, and `isInFoldedCallback` a block inside one, whose calls `listFunctionCardRows` leaves out of the rows (`isLeftOutOfRows`). Neither is a node, so the call is a call row with its selector folded into it, while a call of a library handed a function of the repository, `app.register(routes)`, keeps its node.
- **A component card lists what goes in, what it keeps, what it calls, what runs later and what it renders.** `listComponentCardRows` in `component-card.ts` gives the rows of a node whose block `isComponentCardBlock` (a `component`). `props`: the parameters of the component (`isParameterOf`). `states`: the `state` and `derived` children of the component block that are no memo. `calls`: the calls `listFunctionCardRows` gives, with the calls written on a node the component holds that is no memo, no effect and no trigger, such as `api.todo.create.useMutation({ onSuccess })` (`isHeldCall`, `callSitesOfHeld`), so such a node has a call row in its component. `memos` and `effects`: the inside blocks that are nodes held by the component (`nodeBlockAround`), a memo by `isMemoBlock` and an effect by its type, `effect`, `component-effect` or `effect-callback`. `renderGroups`: one `RenderGroup` per `returnsAt` of the own blocks of the component outside a function written in it (`isInNestedFunction`), in the order written, each with the `render-root` it returns, the one that starts at the `return` or within a line after it inside the block that holds it (`markupOfReturn`), or, for a component with no `return`, one per `render-root` that is a child of the component block, with no `at`. `listRenderRows` gives the rows of a group from its `render-root` and the markup inside it, down to a node block or a `render-event`, in the order of where each starts: a `component` row for each `render` block with a `render` symbol to a `component`, or to an import no file of the group opens that is no library (`isRepositoryComponent`, `componentRenderOf`), a value that wraps a component, `observer(…)`, `memo(…)` or `forwardRef(…)`, counting as that component (`wrappedComponentOf`),, holding the nearest `render-condition` or `render-loop` around it in the markup as its `wrapper` and, as its `branch`, how many component rows before it share that wrapper, so each branch of a ternary is its own row (`withBranches`); a `condition` row for each `render-condition` and a `loop` row for each `render-loop` that holds no component row, since a component row takes the place of every condition and loop around it; and a `value` row for each `value` or `call` symbol of a block of the markup that names a `component` other than the node itself (a function that returns markup is one), at the place of the symbol. `listComponentCardLabels` gives one entry per call, memo, effect, return group and render row (`renderSitesOf`). [Component card](../../../../docs/vocabulary/trace-diagram/component-card.md) has the rules.
- **An effect or a memo card lists what it reads and what it does.** `listHookCallCardRows(nodeBlock)` in `hook-call-card.ts` gives the rows of a node whose block `isHookCallBlock`, read from the call (`hookCallOf`) and the callbacks it is handed. `dependencies`: each use of a value, a read or a call, that is no call of a library, written in the call outside its callbacks, the dependency list, or in a source callback (`isSourceCallback`), each place once. `outsideVariables`: each such use in the other callbacks that names a block outside the node block and no dependency, or an import no file of the group opens, and is no call site, once per block and kind, each with its kind (`kindOfReference`): `import` for an import, `state` or `state-setter` for a `state` or a `derived`, read or called, `prop` for a `root-argument-value`, `constant` for a `root-variable` and a `variable` at the top of a Vue component, `function` for a function, a component, a hook, a method or a class, and `variable` for any other. `calls` and `exits`: those `listFunctionCardRows` gives of the node, the callbacks being its own blocks.
- **A step is a statement, and the statements that follow each other are one step.** The folding is in `step-folding.ts`, which the Code Walkthrough reads too, each with `StepRules` of its own: `statementOf` gives a step the outermost declared value, property or nameless function around it, `isStepRow` folds what is inside a listed block into its row and keeps a changed step inside a condition, a loop, a `try-catch` or a named function, and `listRuns` joins the statements that follow each other and call nothing out (`isFoldedStatement`). `listed-blocks.ts` names the candidates of a node and gives the rules of a trace: a statement that is itself a call out (`isExternalCall`) is of the kind `call`, and a call out among the blocks of a node is a candidate though it has no change, so the line to what it calls has a row to leave. A block calls out by its type, by a next block in another node, or by a call symbol that names a function, a hook, a method, a component or a class outside the node or an import of a library (`callsCodeOutside`). A listed block carries its `statements`, the block of the first one being the block it is listed by. [Steps](../../../../docs/vocabulary/trace-diagram.md#steps) has the rules.
- **A card nests the nodes it holds, as `cards/` says.** Each card every language shares is one `CardRules` in `cards/`: which blocks inside a root block it makes nodes (`isNodeBlock`, read by `isCardNodeBlock` in `node-blocks.ts`), the parent of each node it nests (`listParents`), and the nodes it leaves out (`listLeftOutNodeIds`). `CARD_RULES` in `cards/index.ts` lists them; `listCardParents` merges their parents, the first rule winning, and `nestNodes` in `index.ts` moves each child into `children` and leaves its edges in place. `component.ts`: a component on a chain that another renders is in the first component that reaches it from a top; `countImportersByPath` counts the files that import each file, the components are read in that order, the fewest first, a top is a component no other renders, and a loop is opened at its first component. `class.ts`: each `method` of a `class` is a node in its class (`isMethodOfClass`), a class whose header names another class of the diagram (`extendedClassOf`, read from a `value` symbol of the class block) is in that class, and a method that a class below it writes again is left out with its edges. `returned-function.ts`: a function a `function`, a `hook` or a `method` node returns (`isReturned`) is a node in that node. `isNodeDrawnInside` says a block is such a node, so no row of its parent lists it.
- **A card can group nodes and change the edges.** `CardRules` also says which blocks are no node (`isNotNodeBlock`), which nodes are one node (`groupNodes`, each `NodeGroup` with the ids it stands for and where it is placed), and the edges it adds and leaves out (`listAddedEdges`, `listLeftOutEdgeIds`). `generateTraceDiagram` leaves out nodes, then groups them (`withGroups` remaps the edges onto the group), then applies the card edges (`withCardEdges`), then nests. A part of a library card nests in the node around its owner or its parent (`listPartParents` in `cards/parts.ts`). `route.ts`: every registration of one path is one `route` node with the id `<file of the first>#route@<path>` (`routeGroupIdOf`), a decorated handler, at the root or a method of a class (a NestJS controller), or a handler a route file exports (Next.js), gets a route node of its path and does not nest in its class, a `server-action` stays the node of its own function, a slot that only names its handler is no node, a handler is a child of its route, a line runs from each middleware a registration names, or a decorated handler's decorator names, to its handler instead of from the route or the handler, a line runs from middleware with `routePaths` to each route node of those paths and each node whose root is a `page` part (a Next.js page component), a middleware slot that constructs a class (`new RolesGuard()`) names it as one that names it does, a block that only hands middleware in place (`Depends(…)`) is no node, nor a `root-variable` whose children each name middleware or are such a call (`isHandingMiddleware`, `app = FastAPI(dependencies=[Depends(verify_key)])`), a function whose every statement is a block of a route card, a Fastify plugin, and a `root-variable` whose every child is one, Django's `urlpatterns`, are left out (`onlyRegistersRoutes`), the line from a class to a decorated handler of it is left out, a line runs from a `controller` class to the route node of each of its decorated handlers, and the line from a controller to the middleware its own decorators hand is left out. `router.ts`: each procedure is a child of its router, a router holding no procedure is no node (`holdsNoPart`), and a line runs from the procedure a procedure is built on (`middleware`) to it instead of back. `store.ts`: reducers, thunks, extra reducers, listeners, selectors, cases and endpoints are nodes in their store, state, getters and actions are rows, a holder with no part and a block whose parts all belong to a holder elsewhere are no node, and a line to an RTK Query API from a node that calls a hook it makes, `useGetTodosQuery`, goes to the endpoint `getTodos` instead. `class.ts` also leaves out a constructor that only declares properties or takes parameters and leads nowhere, and leaves a method with a `cardOwner` or a route card to that card (`isDrawnInAnotherCard`); a class whose methods all are, but for a constructor that only declares, has none of its own (`hasMethodsOfItsOwn`), so it folds as a class with no method, and its node is left out when nothing folds it; a class with a `controller` card (`isController`) never folds and is never left out. A NestJS resolver is a router (`router.ts`) whose holder is its class.
- **A library's changes to a card are a `LibraryCardRules`.** One file per library in `languages/<language>/libraries/`, listed in `TYPESCRIPT_CARD_RULES` or `PYTHON_CARD_RULES`, extends one shared card, and `cards/index.ts` picks it by `block.card.library`: its `isNodeBlock` and `isNotNodeBlock` replace the shared ones for blocks of that library, and its other rules are added to the shared ones. Zustand, Pinia, MobX, Valtio, XState and Nano Stores use `ROWS_ONLY_STORE` of `cards/store.ts`, so no part is a node and a selector beside the store is folded into it; Redux and Effector hold their parts as cards.
- **An entry segment keeps its own paths.** With a `scope`, `reachWithin` keeps the steps that lead to a change in the files of the segment, and below a changed root block of the segment, the steps that lead to a change of the shared segment. The shared segment has a `scope` of its own files. A diagram starts at every top of `diffChains` that leads to a change in the files of its `scope`. With segments off, `traceOf` in `src/index.ts` counts the shared files of the group as an entry segment's own and hands the entry's own files as `lineFilePaths`: the diagram then starts at the tops that lead to a change in those files, and adds every other top whose root block that walk reaches, such as an event of a shared component the line renders, until no top is added (`topsWithin`). A shared change no top of the line leads to is not drawn. `withoutOtherLines` then drops every block of a file in `otherLineFilePaths`, the changed files of the other entry segments, and every block that leads to a change only through one, so no diagram draws the line of another segment.
- **`stored.ts` holds the two other forms.** `storeTraceDiagram` replaces every block with its id, keeps the `at` of a block label, and leaves the group out, `linkTraceDiagram` puts them back from a group, and `flattenTraceNodes` gives every node at any depth as one entry with its `parentId` and no children. Snapshots read the stored form, and the MCP tools the flat one.
- **`listTracePaths` in `paths.ts` gives every path of a diagram as a line**, from a node nothing leads to down to its last node, for comparing two diagrams.
- **`listTraceNodes` gives every node at any depth.** Everything that reads the nodes of a diagram as a list goes through it.
