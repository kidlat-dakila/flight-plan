# packages/codegraph/src/journey

The band of a stored Journey Flow Diagram: its filter, its layout, its UI cards and its code views. Read [The UI card](../../../../docs/vocabulary/codegraph/languages/jsx.md#the-ui-card) and [Code views](../../../../docs/vocabulary/journey-flow-diagram.md#code-views) before changing anything here. The rules of [packages/codegraph/AGENTS.md](../../AGENTS.md) hold here too.

## Rules

- **The band groups the components into UI cards.** `journey/ui-cards.ts` builds one tree per top-most `ui` node from the edges between two `ui` nodes, repeats a component under every parent, and lays each tree out as frames and trigger rows with fixed sizes; an event node no row leads to gets a card of one frame. `journey/layout.ts` gives `layoutLayers` one box per card and one per node outside a card, draws no edge between two nodes of a card, and ends every other edge at the port of its row (`listCardPorts`): the right edge of the card for a line that leaves, the left edge for one that arrives. `journey/layered-layout.ts` places the boxes: a box is one column after the last box that leads to it, a box nothing leads to is one column before the first box it leads to, the boxes of a column are ordered by the height of the ports and boxes they connect to and moved as close to level with them as the gap between two boxes allows, and the gap between two columns grows with the steepest line that crosses it. An edge is straight lines only: level across a column, slanted between two columns, and an edge that skips a column crosses it level in a lane of its own between the boxes. An edge is drawn once per place its node is drawn, with `#1`, `#2` after its id. A component with `returns` is laid out as its returns: `toFrameTree` turns it into a frame of the role `group` that holds one frame of the role `return` per return, and each return frame holds the data and the triggers on its lines and the children in its `renderedNodeIds`. A component that another component renders is a `group` too, whatever its returns: with none in `returns`, the group holds one frame of the role `return` that stands for the whole component, with `componentReturn` `null`. A `group` at the top of a card is not a frame: its return frames sit in the card, the card's `headerNode` is the component, and the component's port is the card's header (`headerPortsOf`). A return frame has no port. The band carries the cards as `uiCards`, and a node or an edge drawn inside one has `isInsideCard`. `journey/build.ts` adds one node of the kind `return` per return frame, so that choosing the frame opens the return's label, description and traced lines; a frame's `nodeId` is what it opens and its `ownerNodeId` is the component it is hidden with. An edge of the band has its two ends and its points only: the page draws every edge as the same line with no label, and the `kind`, `certainty` and `through` of the stored edge stay in the artifact for the agent.
- **The band turns code views into rows.** `journey/code-views.ts` gives a node of the band one `NodeCodeView` per stored view whose file has a source: a heading, a count label, the path, the range, a note for a file outside the segment's `changedPaths`, the link, and `rows` of the walkthrough's row shapes. A span is a `lines` row read from the source as the Code Walkthrough reads it, two spans are divided by a `gap` row, and a `waypoint` row with the waypoint's own view stands before the first span that overlaps its range. `listWaypointPlaces` in `walkthrough/build.ts` gives the visible waypoints with their ranges, and the caller hands them to `buildJourney`. A node with no code view keeps its `codeLinkId`, and the page then shows its whole declaration.
