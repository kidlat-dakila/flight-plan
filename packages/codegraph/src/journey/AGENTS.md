# packages/codegraph/src/journey

The band of a Journey Flow Diagram: what the review page receives. Read [On the page](../../../../docs/vocabulary/journey-flow-diagram.md#on-the-page) before changing anything here. The rules of [packages/codegraph/AGENTS.md](../../AGENTS.md) hold here too.

## Rules

- **The band has no positions.** `buildJourney(segment, scope, places, context)` in `build.ts` turns the nodes of a segment's diagram into `JourneyNodeView`s, nested as the nodes are, and the edges into their ids and their two ends. `packages/ui` places them.
- **A node view is words and code.** It carries the `type` and its label from `BLOCK_TYPE_LABELS`, the written label or the name of the code as a draft, the `name` of the code, the `shortPath` of the file, which is its last two folders and its name at most (`routes/orders/index.tsx`), the description as prose, and `change`: `added` when every line of the block the node stands for is new, `modified` when the node has another change, `null` when it has none.
- **A block is named in one place.** `nameOfBlock` in `names.ts` gives the name of a block, the name the catalogue gives it, or its type and its line. An effect with no name is named after what it calls, `useMutation`. A `render-event` is named after its element and itself, `button.onClick`. A member read from an argument is named after the argument and itself, `props.onSave`. The band, the code links and the backend's node tools all read it.
- **A node lists its arguments, its state, its hooks, its effects and its steps.** `toBlockLists` in `build.ts` reads the listed blocks of a node from `listListedBlocks` of `journey-flow-diagram/listed-blocks.ts`, gives each the label of its `blockLabels` entry, or the name of its code as a draft, and gives one `blockLists` entry per kind that has a block, in the order `argument`, `state`, `hook`, `effect`, `step`. A hook is an `external-value` with a call of a name that starts with `use` and a capital letter, listed under that name. An effect inside a `state` or a `derived` declaration of the node is listed as that declaration, under `state`, whether or not a chain passes through the declaration. A step is any other block that `isStepBlock` names, that is a node of its own or that has a change, but an event, a data fetch, markup and a function written in place of an event or a callback. A block inside a listed block is left out, unless it has a change.
- **A row carries the lines of its block.** Each listed block and each trigger label has `lines`, the line spans of its block, so the page can focus the code of the node on them.
- **A row is changed when its block is, or the function written in place of it.** `changeOfBlock` marks an event whose arrow function changed.
- **A line leaves the row of the block that takes the step.** `toEdgeViews` gives an edge one view per step between its two nodes (`listNodeSteps` of `journey-flow-diagram/node-blocks.ts`), and one from the row of an inner node's block to the head of that node. A step that leaves the block of a node, or reaches it, has no row on that side.
- **A node shows the code of its block.** `buildNodeCodeViews` in `code-views.ts` gives a node one view of the lines of the block it stands for, read from the source as the Code Walkthrough reads it, with a `waypoint` row before the first lines a waypoint covers and a note for a file outside the segment's `changedPaths`. `listWaypointPlaces` in `walkthrough/build.ts` gives the visible waypoints with their ranges, and the caller hands them to `buildJourney`.
