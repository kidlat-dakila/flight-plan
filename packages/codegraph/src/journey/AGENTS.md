# packages/codegraph/src/journey

The band of a Journey Flow Diagram: what the review page receives. Read [On the page](../../../../docs/vocabulary/journey-flow-diagram.md#on-the-page) before changing anything here. The rules of [packages/codegraph/AGENTS.md](../../AGENTS.md) hold here too.

## Rules

- **The band has no positions.** `buildJourney(segment, scope, places, context)` in `build.ts` turns the nodes of a segment's diagram into `JourneyNodeView`s, nested as the nodes are, and the edges into their ids and their two ends. `packages/ui` places them.
- **A node view is words and code.** It carries the `type` and its label from `BLOCK_TYPE_LABELS`, the written label or the name of the code as a draft, the path of the file, the description as prose, and `change`: `added` when every line of the block the node stands for is new, `modified` when the node has another change, `null` when it has none.
- **A block is named in one place.** `nameOfBlock` in `names.ts` gives the name of a block, the name the catalogue gives it, or its type and its line. A `render-event` is named after its element and itself, `button.onClick`. A member read from an argument is named after the argument and itself, `props.onSave`. The band, the code links and the backend's node tools all read it.
- **A node lists its arguments, its state, its hooks and its effects that are on a chain.** `toBlockLists` in `build.ts` reads the `codeBlocks` of a node after the first and gives one `blockLists` entry per kind that has a block, in the order `argument`, `state`, `hook`, `effect`. A hook is an `external-value` with a call of a name that starts with `use` and a capital letter, listed under that name. An effect inside a `state` or a `derived` declaration is listed as that declaration, under `state`, whether or not a chain passes through the declaration. Any other effect is named after what it calls. A block inside a listed block is left out.
- **A node shows the code of its block.** `buildNodeCodeViews` in `code-views.ts` gives a node one view of the lines of the block it stands for, read from the source as the Code Walkthrough reads it, with a `waypoint` row before the first lines a waypoint covers and a note for a file outside the segment's `changedPaths`. `listWaypointPlaces` in `walkthrough/build.ts` gives the visible waypoints with their ranges, and the caller hands them to `buildJourney`.
