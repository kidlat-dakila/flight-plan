Say what crosses the edge, not that it is a call. The arrow already says one
thing leads to another, and both cards carry their own names.

- On a **call**: what is handed over — "the basket", "id + path", "every id at
  once". Never the method, which the card at the head of the arrow already is.
- On a **fork arm**: the condition that chooses it, in the terms the code tests
  — "out of stock", "a NUL byte". Never "yes", "no", "true", "false".
- Never a verb about the call itself: "calls", "uses", "passes to", "then".

**Leave it off where the two cards already answer it.** A board where every
arrow is labelled has no emphasis left for the two that matter.

**Every arm of a split says what chose it.** A bare arm reads as the only path
rather than as one of two. The arm the code takes when nothing matched states
what is true *and* marks itself: "a NUL byte" on one, "no NUL byte (else)" on
the other. The marker does not count against the words.
